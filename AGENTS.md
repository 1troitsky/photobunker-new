# PhotoBunker New — правила разработки

**Репозиторий:** `1troitsky/photobunker-new`. **Актуальное решение владельца от 2026-10-29:** независимая реализация оставшихся Issues силами ChatGPT, **без ожидания Codex/merge**, затем общая независимая проверка и интеграция Codex. Специальная норма процесса — [14 — Independent Development Pipeline & Replaceable UI](docs/14-INDEPENDENT-DEVELOPMENT-PIPELINE.md). Владелец сохраняет полномочия по продуктовым решениям, UX и выпуску. Codex не подчиняется ChatGPT; ChatGPT не меняет `main`.

Если evidence отсутствует, ChatGPT самостоятельно проводит узкий read-only legacy-check и документирует его в этой Issue до кода. Codex и ChatGPT не изменяют старый репозиторий/`_old`; ChatGPT читает legacy через GitHub. Пропускать сверку нельзя;

## 2. Технические инварианты

- **Новый проект без слепого массового переноса legacy.** Новый [самостоятельный product baseline](docs/13-PRODUCT-ACCEPTANCE-BASELINE.md) — нормативный источник требований, а старый PhotoBunker — **обязательный read-only источник уже сделанной реализации, UX, assets, алгоритмов и test vectors для каждой Issue**. В Phase I ChatGPT самостоятельно классифицирует релевантные части до кода; в Phase II Codex независимо проверяет эту классификацию. Пригодное переиспользуется или адаптируется, дефектное явно отклоняется. Огромные Vue stores, plaintext prototype, Matrix/RTC/чаты исключены.
- **UI-first + production-first:** R2-01 — фундамент/production build и проверяемый HTTPS preview, R2-02 — пять экранов для первой приёмки владельца; не ждать завершения всех 26 Issues. Выпускать и тестировать реальный `build`, не только dev.
- **Anonymous key-only Identity:** никаких email, телефона, username/password или server reset. Единственный Account Recovery Key содержит locator+секрет; trusted devices используют challenge signatures. Потеря ключа и всех устройств необратима. Account wrapping key только оборачивает отдельные per-asset DEK и никогда не шифрует весь архив напрямую. См. [11](docs/11-IDENTITY-AND-KEYS.md).
- **Local-first:** shell не ждёт HTTP; capture → encrypt → durable Dexie/IndexedDB photo metadata/journal/outbox + OPFS ciphertext (encrypted IndexedDB Blob fallback) → Garage S3 sync **позже, не в R2-01**. Pinia — ephemeral UI. Browser storage capabilities/persist, trusted time and clock rollback tested per [12](docs/12-CLIENT-STORAGE-AND-TRUSTED-TIME.md).
- **Фото только зашифровано при постоянной локальной записи**, не попадает в системные Photos/DCIM, приватные metadata в DB защищены. Ключи, PIN, GPS, фото, EXIF и токены не протекают в logs, URLs, analytics, plaintext caches.
- **Режимы задания:** 1 — camera bytes без дополнительного сжатия, видимый disabled; 2 — compressed original + separate edit; 3 — compressed master replaced after edit, default. Выбранный режим фиксируется при capture, старые assets заменяются crash-safe.
- **Thumbnails:** максимум одна зашифрованная WebP миниатюра 320 px по длинной стороне на фото, S3 + ограниченный зашифрованный кэш; отдельный постоянный preview отсутствует.
- **Storage TTL:** срок снимка по заданию **24 часа — 45 дней**, после expiry закрыть доступ и удалить original, master, edits, thumbnail, share/export, кэш и записи БД. Эффективный TTL фиксируется при съёмке; Laravel Scheduler + очередь с indexed expiry и batch jobs; локальный клиент убирает просроченное при возобновлении работы. См. [03](docs/03-PHOTO-STORAGE.md).
- **Фото, Photo Card, Note, Assignment, Team и Photo Browser — разные сущности и scopes.** Сервер проверяет ACL/TTL; PIN блокировки, локального удаления и emergency — разные механизмы. Доступ/удаление нельзя подтверждать прежде фактического источника истины.
- **Модульные границы:** domain/application/infrastructure/ui с публичными контрактами; no cyclic feature imports, no UI raw crypto/S3/DB SDK, no giant shared store. Локальная обязательная проверка должна ловить нарушения.
- **Production security/UX:** mobile + desktop, RU/EN, offline, restart, permission denied/storage full, same/different accounts, revoke/expiry. Не называть непроверенное production-ready. Избегать destructive legacy migration.
- **Legacy isolation:** репозиторий `1troitsky/photobunker` и любой каталог `/_old/**` только для чтения. Никогда не редактировать, stage, commit, format или переносить их содержимое массово; `/_old/` обязан быть в `.gitignore`.

## 3. Независимая реализация → общая проверка и интеграция

1. **Владелец** утвердил последовательную реализацию всех оставшихся Roadmap Issues без ожидания review, merge или выдачи следующей Ready Issue со стороны Codex. **ChatGPT** самостоятельно проверяет scope, нормативные контракты, actual SHA main/upstream и зависимости **в незалитых ветках**, формирует missing `Legacy evidence` в существующей Issue, затем выполняет один Issue за раз.
2. **Каждая функциональная Issue** — `chatbot/r2-XX-<slug>` ветка от последнего необходимого upstream SHA и **один Draft PR** с `Closes #N`. Для незалитых зависимостей `base` — предыдущая ветка (stacked PR), для уже интегрированных — `main`. Scope diff — **`base...HEAD`**, а не `main...HEAD` для стеков. Не менять `main`, не force-push, не merge/auto-merge.
3. ChatGPT выполняет доступные проверки, пишет проверяемый код и честный `NOT RUN`. После открытия Draft PR **не ждёт Codex** и по согласованной очереди переходит к следующему Issue. Ошибка в upstream исправляется в исходном PR с обычным переносом исправления в downstream без переписывания истории.
4. **Codex** после завершения Phase I **независимо проверяет весь стек**, устанавливает/настраивает окружение, запускает тесты, исправляет код в соответствующих PR, приводит зависимости в порядок и **последовательно интегрирует** в `main`, повторяя CI/E2E на общем состоянии. Только затем owner device UX acceptance и release-gates. **Исключение:** этот governance PR Codex проверяет и интегрирует сейчас, чтобы утвердить новые правила.
5. **UI/UX должен оставаться полностью заменяемым presentation layer.** `ui/` — только view-state/view-model и public typed use-cases, никакого raw DB/HTTP/crypto и бизнес-правил. Продакшен-сценарии и local-first/optimistic/retry/TTL/ACL принадлежат application/domain/infrastructure. Общие design tokens/primitives, независимая композиция mobile/desktop, никаких циклов/god-store. Подробнее: [14](docs/14-INDEPENDENT-DEVELOPMENT-PIPELINE.md).
6. Отсутствие утверждённого визуального дизайна/раннего UX-preview **не блокирует написание следующих Issues**, но блокирует `Accepted/Released`, пока замечания не устранены. Критические safety STOP действуют для опасной функции; не делать ложных заявлений о готовности. GitHub Project статус не подменяет фактический статус исполнения; `Implemented (Draft)` не равно `Verified/Integrated`.

## 4. Stop / escalation

Непроверенное шифрование, plaintext disk, автоэкспорт в системную галерею, поздние ACK воскрешают фото, файлы живут после разрешённого expiry, S3/DB orphan без cleanup, сломанный production camera, обход ACL, безвозвратная потеря неистёкшего unsynced снимка — STOP. При обнаружении defect ChatGPT фиксирует проблему и по возможности исправляет её безопасно в Phase I, не расширяя scope; после завершения стека Codex независимо проверяет и исправляет оставшиеся дефекты. STOP не препятствует разработке незатронутых Issues, но запрещает опасное продолжение затронутого сценария и исключает Verified/Integrated/Accepted до исправления. Только владелец утверждает изменение продуктовых правил.
