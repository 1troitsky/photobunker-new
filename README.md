# PhotoBunker — новая архитектура (проектирование)

> **Статус: подготовка к разработке.** Roadmap и Issues готовятся заранее; реализация начинается только с явно разрешённого Ready Issue. OPEN решения нельзя додумывать.
> Дата исходной фиксации: 2026-10-28.

Этот репозиторий — **новый, независимый проект** для пересборки PhotoBunker. Старый проект `1troitsky/photobunker` остаётся источником требований, проверяемых контрактов и потенциально пригодного к переносу кода, **не** шаблоном архитектуры. Его `main`, хранилища и данные не затрагиваются.

## Продуктовый scope

- Камера, пресеты и фотографии/галерея.
- Задания: правила съёмки, участники, роли, доступы, связь с фотографиями.
- Photo Browser: подборки по заданиям и авторизованный просмотр.
- Редактор фотографий.
- Photo Card: описание, доступы, представления и публикация.
- PIN: блокировка приложения, локальное удаление и экстренный сценарий — **отдельные** понятия.

**Мессенджер, Matrix, звонки и обсуждения не входят в эту версию.** Наличие у задания участников не означает наличие чата.

## Что зафиксировано и что ещё нет

**Подтверждено владельцем:**
1. Нельзя повторять самописную взаимозависимую frontend-архитектуру. Систему нужно делать устойчивой к локальным ошибкам и простой для исправления.
2. **Все Issues создаются заранее из единого roadmap**, чтобы любой новый чат видел полный план. Нельзя начинать код, создавать ветки разработки или PR без утверждённого Ready Issue и разрешения владельца.
3. Local-first, мгновенная навигация из локального разрешённого состояния, проверка **production**, не только dev.
4. **Режимы фото утверждены (ST-02/ST-03):** в настройках задания три режима — (1) исходный снимок без дополнительного сжатия, **пока disabled в интерфейсе**; (2) сжатый оригинал отдельно, отредактированный результат отдельно; (3) сжатый оригинал с заменой при редактировании — **по умолчанию**, также без задания. Ненужные долгоживущие копии, thumbnails, previews и сироты не допускаются.
5. **ST-01 — утверждено 2026-10-28:** гибридное хранение: сначала локальное сохранение фотографии на устройстве, затем фоновая синхронизация с S3. Открытие локального фото и навигация не ожидают S3. Точный S3-провайдер, политика последующей очистки локальных данных и восстановление на другом устройстве — отдельные решения.
6. **ST-12/ST-13 — утверждено 2026-10-28:** метаданные съёмки записываются в отдельную локальную БД одновременно с локальным сохранением фото и позднее синхронизируются с серверной БД. Локальные изображения и чувствительные метаданные хранятся **только зашифрованными**. PhotoBunker **не записывает фото в системную галерею/Photos/DCIM**; внутренняя галерея приложения разрешена.

**Пока НЕ утверждено:** формат/качество сжатия, реальная схема метаданных и E2EE-полей, конкретная реализация локального хранилища, свой Garage или внешний S3, политика очистки синхронизированных локальных копий, восстановление на другом устройстве, размер и размещение миниатюр, постоянная история редактора, TTL, технологический стек, схема API и этапы реализации.

## Правила для любого будущего агента

Перед действиями прочесть **всю документацию из индекса**, особенно AGENTS, COLLABORATION, roadmap, security/storage и назначенный Issue. Не переносить старые `apps/web` компоненты/mega-stores автоматически; не начинать реализацию по инициативе агента. Все Issues разрешено создавать заранее по roadmap; код — только после Ready и санкции владельца. Если решение не принято, сохранить его как **OPEN**, а не угадывать.

Разработка должна быть направлена на законченный продукт, а не на демонстрационные имитации. Сейчас цель — завершить подготовку документации, Project и Issues; реализация начнётся по разрешённой Ready-задаче.
