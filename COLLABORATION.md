## 2. Роли, без двусмысленности

### ChatGPT — основной разработчик и координатор

- Совместно с владельцем проектирует архитектуру, фиксирует решения и изменения в едином roadmap/контрактах.
- Планирует последовательность, сопровождает Issues/Project **при наличии необходимых GitHub полномочий**. Если для действия нет инструмента, точно описывает одно необходимое действие владельцу; **не передаёт организационную работу проверяющему агенту по умолчанию**.
- **Сам реализует функциональность и пишет код**, создаёт ветку `chatbot/<task-id>-<slug>`, делает один Draft PR с `Closes #N`; соблюдает `main`-protection.
- Анализирует замечания Codex, **сам вносит исправления в тот же PR** и заново передаёт изменённый diff на проверку. Не просит Codex «дописать приложение», исправлять за автора или расширять scope.
- Обеспечивает доступную проверяемую **production preview** на согласованных вехах. Если сам не может выложить тестовый стенд технически, честно указывает блокировку и предлагает точный сценарий развёртывания, а не притворяется, что URL существует.
- Документирует выполненные/невыполненные тесты, факты переноса кода, byte/storage и security последствия.

### Codex — только независимый проверяющий агент

- Получает Draft PR/commit SHA, полный diff, сценарии acceptance и применимые docs.
- **Не разрабатывает функционал самостоятельно.** Не является вторым разработчиком, не создаёт новые функции, архитектурные решения, Issues или PR по собственной инициативе.
- Выполняет independent code review: imports/dependency boundaries, контракты, безопасность, SQL/migrations, данные, корректность local-first, storage budget, E2EE, ACL, TTL, PIN.
- Запускает имеющиеся и, если требуется, **пишет или улучшает проверочные тесты/тестовые сценарии**, воспроизводит дефекты на production build и реальных API/staging; фиксирует конкретный воспроизводимый результат и команду.
- Оформляет замечания в существующем PR/Issue и возвращает ChatGPT с `PASS / FAIL / BLOCKED / NOT RUN`. При обнаружении дефекта **ChatGPT исправляет функциональный код**; Codex перепроверяет.
- Не сливает PR, не изменяет `main`, не объявляет продукт Accepted, не принимает продуктовые решения. Изменять код/тесты в рабочей ветке автора или выполнять merge — **только по отдельному явному разрешению владельца**, не по умолчанию.

### Владелец — продуктовые решения и приёмка

- Утверждает architecture/UX/storage/security choices, приоритет и разрешение запуска реализации.
- Проверяет реальные milestone builds на телефоне/desktop: UI после R2-02, настоящие локальные фото после R2-06, затем S3/галерея, задания, редактор/Card, Browser/PIN и финальный релиз.
- Решает, принята ли функция и можно ли интегрировать PR. **Без явного разрешения на merge никто из агентов не выполняет merge**. Если договоримся об ином автоматизированном режиме, отдельно изменим правило.
- Не обязан лично запускать тестовый стек или каждый день переписывать агенту требования.

## 3. Настройка GitHub Project

Планируемая доска: **PhotoBunker New — Development**, owner `1troitsky`, repository `1troitsky/photobunker-new`. Поля:
- `Status`: **Backlog → Ready → In Progress → Review → Integrated → Accepted**; дополнительные **Blocked**, **Cancelled**.
- `Priority`: P0/P1/P2; `Phase`: R2-0…R2-7; `Owner` (исполнитель или проверяющий); `Risk`: security/storage/UI/infrastructure.
- Views: Board by Status, Roadmap by Phase, Blocked / Open Decisions.
- WIP: у ChatGPT не более **одного** активного implementation Issue; у Codex не более **одного** PR в независимой проверке.

Project v2 — не равно Issues. На дату подготовки доступный GitHub connector не позволяет **создать Projects v2**. Поэтому доска и связанные статусы не считаются существующими до проверки. Её создание в GitHub UI выполняет владелец, если прямое подключение не появится; **не ждать от Codex реализации Project как части проверки кода**.

## 4. Definition of Ready

Issue может стать Ready, когда:
- владелец разрешил необходимый scope и нет OPEN решений, блокирующих конкретную задачу;
- предыдущие зависимости уже интегрированы, acceptance критерии, error/offline/reload/security/UX states понятны;
- ChatGPT знает, как доказать работоспособность на production build и где владелец сможет её проверить;
- не требуется Matrix/чат/RTC, конфликтующий с утверждённой архитектурой;
- нет явного запрета владельца или security No-Go.

**Все 26 Issues заведены заранее**, но их нельзя все переводить в Ready автоматически. Зависимые от storage решений tasks остаются Backlog/Blocked. Утверждение UI foundation не требует окончательного выбора thumbnail формата или S3 провайдера.

## 5. Реальный цикл одной задачи

1. Владелец даёт разрешение на старт соответствующего этапа; **ChatGPT**, не Codex, организует первую незаблокированную Issue и проектирует её реализацию.
2. **ChatGPT пишет код** в своей ветке, проводит доступные проверки, читает полный diff и открывает **Draft PR**.
3. **Codex получает PR, независимо проверяет и тестирует** реальную production-сборку, пишет замечания с воспроизведением, не сливает и не дорабатывает основной функциональный код.
4. **ChatGPT исправляет замечания** в той же ветке и возвращает на повторную независимую проверку. Цикл повторяется до PASS с указанием NOT RUN и ограничений.
5. После положительного review **владелец отдельно разрешает merge**. Выполнить merge может уполномоченное лицо/инструмент при явной команде; только тогда статус `Integrated`.
6. На milestone **владелец проверяет production HTTPS preview на своём устройстве**, утверждает `Accepted` либо возвращает конкретные ошибки ChatGPT. Codex может дополнительно перепроверять исправления.
7. Следующий зависимый этап начинается после технического и продуктового gate. Не ждать конца всех 26 Issues до первого ручного теста.

**Вехи:** R2-01 строит инфраструктуру production HTTPS preview; R2-02 — первая ручная UX-проверка; R2-03/04/06 — первая реальная encrypted offline camera/gallery проверка без S3; R2-05/07 — облако и полная галерея; далее задания, редактор, Card, Browser, PIN. [Полная матрица](docs/08-ROADMAP.md).

## 6. Независимость проверки и стоп-правила

- Проверяющий Codex не утверждает, что «сам проверил», если не запускал тесты; `NOT RUN` сопровождается причиной.
- Red production build, plaintext at rest, запись в системную галерею, потеря единственной unsynced копии, fail-open ACL/TTL, неверный PIN/emergency сценарий или CI bypass — **FAIL / BLOCKED**.
- ChatGPT не обходит review и не выставляет `Accepted` самостоятельно. Codex не подменяет результат владельца даже при зелёных тестах.
- После каждых четырёх Integrated ChatGPT обновляет статус препятствий/архитектурных рисков в Project/Issue; Codex предоставляет независимые результаты проверки.
