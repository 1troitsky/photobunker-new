# PhotoBunker API

Laravel 13 JSON API with a temporary local prototype library. Use the repository
OrbStack/Compose setup; host PHP/Composer are not required. The framework APP_KEY
is never a user's photo decryption key.

Health endpoints remain `/api/v1/health` (process only) and `/api/v1/ready`
(database connectivity). Readiness does not test storage. Operator commands
`photobunker:storage-check --signed` and `photobunker:storage-configure` retain
their synthetic-fixture/private-bucket checks and sanitized output.

The new `/api/v1/prototype` endpoints create an isolated library with a random
256-bit bearer code, upload originals/thumbnails, list/read, update metadata with
revision preconditions and delete. They require local/testing environment and
an enabled prototype flag; production always returns 404. This is deliberately
plaintext interim functionality authorized by the owner, not the product's
E2EE/auth/recovery implementation. No conventional email/password provider or
browser session is introduced. Only token hashes are stored on the server.

[API contract](../../contracts/local-prototype-api.md) and
[runbook](../../docs/operations/server-prototype.md) describe the protocol,
limits, failure behavior, tombstones and cleanup. `prototype_*` tables and the
`prototype/` storage prefix stay separate from future protected data. Servers
stream bytes without image decoding; thumbnails are generated by the browser.

Reservations are committed before S3 I/O and count against library quotas.
Active visibility follows both object writes and HEAD sizes. Identical upload
retries return one record. Deletion revokes access before physical cleanup;
tombstones block stale upload resurrection. The scheduler retries incomplete
deletions and expires abandoned reservations after an hour. Active-photo TTL,
backup/restore policy, production auth, encryption and audit are future work.

All errors use the safe `error.code/message_key/request_id/retryable` envelope.
Exception reports contain only class and request ID; requests, headers, SQL,
captions, access codes and provider URLs must never be logged. API/media are
private/no-store/no-referrer/nosniff, with no public symlink or permanent URL.

Tests run in isolated SQLite memory with fake storage; phpunit.xml forces both
env and server values because Docker/Artisan may prepopulate $_SERVER. TestCase
refuses any other database before RefreshDatabase can act. Run tests and Pint
through `./scripts/dev api`; browser integration tests exercise actual local
PostgreSQL/Garage separately with generated fixtures. Desktop tests do not
establish iPhone or installed-PWA reliability.

Normative final requirements remain in `_docs/06`, `07`, `11`, `12`. This local
plaintext prototype does not satisfy their security/privacy acceptance.
