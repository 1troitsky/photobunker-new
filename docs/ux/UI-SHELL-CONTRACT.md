# PhotoBunker — Unified UI Shell Contract

**Статус:** **OWNER-APPROVED / NORMATIVE FOR FUTURE UX SCREENS** (дизайн). Production-интеграция не означает, что это уже реализовано. Документ обязателен для любого агента, создающего новый экран в `docs/ux/` или внедряющего его в Vue.

Основание: согласованные владельцем экраны Assignments, Assignment Editor, Browser, File Viewer (ранее Photo Viewer, Fieldwork). Самый существенный запрет: **НЕ СОЗДАВАТЬ новую концепцию шапки, логотипа и dock для каждой страницы.**

**Исключение: Welcome Page 1.4, явно принятое владельцем.** [Эталон](welcome/accepted-welcome-v1.4-standalone.html) · [описание](welcome/README.md). Внутренняя палитра и скругления наследуют согласованный Fieldwork.

## Неизменная оболочка

1. **Header**: высота **64px**, фон `#181818`, нижний разделитель `#303030`. Слева квадрат `[pb]` (37×37px, mobile может 34×34px), затем **PhotoBunker** с системным статусом **строго под названием** и точечным индикатором. Цвет основного текста `#f3f3f3`; статуса `#aaa`; акцент `#1ed760`. Никаких чёрных надписей на тёмной панели.
2. **Контекстные действия в Header**: положение справа, обычные иконки **без отдельных обводок/заполненных карточек**, тот же размер/кнопочная геометрия. **Состав кнопок меняется в зависимости от страницы**, не их стиль или высота. Например, Browser v3 — Новая папка / Загрузить файлы / Выбор / Поиск / Настройки (Поделиться — в меню объекта); File Viewer — Избранное / Копировать (для видео — кадр; для аудио недоступно) / Скачать / Удалить. Нельзя незаметно вернуть кнопки в другое место или дублировать их.
3. **Основной контент**: единственная изменяемая область между Header и dock. Экраны могут использовать scrolling или фиксированную grid-разбивку с `minmax(0,1fr)`, как File Viewer. Не позволять содержимому сдвигать Header/dock при изменении размеров изображения или текста. Реальный viewport и safe area — через production layout, без `100vh`-ошибок iOS.
4. **Dock**: высота **82px**, фон `#181818`, верхний разделитель `#303030`; по умолчанию **5 пунктов: Задания / Browser / Камера / Контакты / Профиль (Настройки)**. **Fieldwork Appearance 1.3 разрешает пользователю 3–6 пунктов** (рекомендовано 4–5) из Задания / Browser / Камера / Уведомления / Профиль / Контакты / Сообщения, менять порядок и состав. **Профиль / Настройки всегда присутствует**, но свободно перемещается. Все зоны равной ширины; неактивный цвет `#999`, активная иконка/название `#1ed760`. Положение Dock не скачет, safe areas соблюдаются. Повторный tap активного пункта — один уровень назад внутри раздела; в редакторе Dock эта подсказка не отображается. Исключения: явно утверждённые fullscreen-экраны/модальные слои могут перекрывать Shell.
5. **Path bar в Browser и File Viewer**: одни и те же классы и оформление: прозрачный фон, **нет рамки**, стрелка возврата на уровень выше и горизонтальный breadcrumb. File Viewer — часть Browser, он не получает «свой» path bar.
6. **Слои**: popover под кнопкой, затем штатные bottom sheets и In-App Browser / fullscreen поверх Shell. Слои не должны менять геометрию Shell, терять фокус или перекрывать текст непрозрачным лишним оверлеем. Контраст фиксируется отдельно для тёмного приложения и независимого web-content внутри In-App Browser.
7. **Системные уведомления**: статус Header представляет **единый источник** состояния операций для всего PhotoBunker. Нажатие открывает журнал, включающий текущую операцию и предыдущие ошибки/предупреждения; разные страницы **не должны** создавать несовместимые status-bars или скрытые toast-only ошибки.
8. **Анимации**: согласованные естественные переходы, не отвлекающие от содержания, с `prefers-reduced-motion`. Панели плавно открываются снизу, жесты корректно отменяются, fullscreen отклоняется в сторону вертикального свайпа, переход между кадрами не перестраивает экран. Избегать нескольких независимых анимационных систем с разным поведением.

## Архитектурное правило внедрения

В production создать/переиспользовать **ОДИН** layout/компонент общей оболочки (например, через действующий App Shell), с **контекстным слотом действий** и **одним** status controller/store. Экран передаёт действия и основное содержимое, **не реализует повторно header/dock**, не дублирует status logic. Не переносить demo HTML/CSS слепым копированием: сначала проверить действующие Vue-компоненты и роуты. Не менять `main` и не переносить в production без отдельного scope/PR и тестов.

Примечание по будущему «Избранному»: у Photo Viewer выбран вид **закрашенной звёздочки**. В Browser при добавлении первого фото требуется автоматически показать раздел/папку «Избранное». **Виртуальная коллекция vs файловая папка, модель и синхронизация требуют отдельного решения**, без дублирования фотографий. См. `browser/viewer/README.md`.

Примечание по будущему Share: возможность делиться фотографиями или целым заданием сохранена в `browser/SHARING-OPEN-QUESTIONS.md` как **OPEN / DO NOT IMPLEMENT**.

## Acceptance gate для каждого нового экрана

Перед заявлением о завершении агент должен сравнить с предыдущими эталонами: header, бренд/статус, порядок контекстных действий, dock, его высоту, safe area, контраст, клавиатуру и экранные слои. Обязательны проверки portrait/landscape, мобильного браузера, desktop и reduced motion. Публичные ссылки/ACL/ключи/TTL **не изменяются** из-за визуального проекта. Недоступные проверки честно отметить как `NOT TESTED`, не писать «готово» только по наличию компилируемых файлов.
