## Внешний вид

- **Полноэкранный экран блокировки без Header и Dock**, с прежней тёмной нейтральной палитрой Fieldwork и зелёным акцентом `#1ed760`.
- По центру: логотип PhotoBunker (**54 px**), небольшое название продукта, заголовок **«Введите PIN» (21 px)** и индикаторы введённых цифр.
- Компактная цифровая клавиатура **максимальной ширины 248 px** с тремя колонками, кнопками 0–9 и клавишей удаления последнего символа. Кнопки доступны для касания и управления одной рукой; не восстанавливать более широкую версию 1.0 без нового запроса владельца.
- Нет биометрии, круглых внешних action-кнопок, отдельного выбора аварийного режима или рекламных блоков. Фон/геометрия фиксированы; не вызывать скачки при вводе.

## Поведение

- При настройке обычного PIN принимаются **4–8 цифр**; количество индикаторов соответствует **уже сохранённой** длине обычного PIN, а не свободно выбирается во время разблокировки.
- Ввод цифрами на экранной и физической клавиатуре; `Backspace` удаляет последнюю цифру, `Escape` в HTML сбрасывает ввод. По достижении заданной длины — проверка и аккуратный визуальный ответ. **Не выводить сам PIN** в интерфейсе обычного устройства.
- **Обычный PIN и Emergency PIN распознаются одним и тем же полем ввода**. Нет отдельной кнопки «Экстренное удаление». Для реального приложения проверка, ограничение попыток и destructive действие по аварийному PIN должны быть надёжным процессом из [SECURITY-PIN-DEVICE-CONTRACT.md](../../product/SECURITY-PIN-DEVICE-CONTRACT.md).
- В эталоне только демонстрационная проверка: `2468` при выборе четырёх цифр и другие тестовые значения при пяти-восьми цифрах. **Не переносить demo PIN, `demoCodes`, сравнение строк и временные задержки в production**, не хранить реальные PIN в открытом виде. При ошибке ввод сбрасывается; реальная защита должна иметь rate limiting/cooldown и fail-closed.
- Сохранять `prefers-reduced-motion` и нативную работу в мобильном PWA (safe area, ориентация, экранная клавиатура). Страница блокировки не должна раскрывать содержимое данных до подтверждённой разблокировки.
- Активация Emergency PIN **не может** быть восстановлением доступа; серверный revoke/delete intent при offline остаётся `pending` до ACK, не обещать уничтожение удалённых объектов по одному нажатию.
