# Welcome Loader — Fieldwork 1.6

**OWNER-SELECTED EXTENSION OF WELCOME 1.4 / NOT PRODUCTION IMPLEMENTED.** 2026-11-09 владелец запросил состояние загрузки того же Welcome и поправил текст на **«Входим в приложение...»**. Следующим сообщением поручил добавить Loader в текущий PR перед началом PIN Shell. Эталон Welcome 1.4 не переписан.

## Исходники

- [index.html](index.html), [style.css](style.css), [app.js](app.js) — раздельная версия.
- [accepted-welcome-loader-v1.6-standalone.html](accepted-welcome-loader-v1.6-standalone.html) — точный автономный HTML состояния Loader 1.6, показанного владельцу.
- Для локального открытия запустить `python3 -m http.server 8080` из корня репозитория, открыть `http://localhost:8080/docs/ux/welcome/loader/`.
- **Welcome 1.4** остаётся отдельно: [../accepted-welcome-v1.4-standalone.html](../accepted-welcome-v1.4-standalone.html). Не менять его согласованный CSS/JS/иллюстрации ради состояния Loader.

## Поведение

- **Одна и та же Welcome-страница**, не новый экран приложения и не отдельный Shell. Логотип, фон, карусель с шестью иллюстрациями, мягкое свечение, её точки и анимация сохраняются без визуальных изменений.
- В режиме **Loading** на месте **обоих** действий «Создать аккаунт» / «Восстановить аккаунт» появляется небольшой зелёный spinner и подпись **«Входим в приложение...»**. Не показывать одновременно кнопки и индикатор загрузки.
- Позиция слота действий не меняется: композиция не прыгает при переходе из Welcome в Loading.
- Встроенный **Welcome / Loading** и **Телефон / Desktop** — только контролы preview, не переносить в production.
- Loader не должен блокировать уже подтверждённую локальную сессию ожиданием HTTP/Matrix; проверять identity/session асинхронно, показывать правильное состояние и иметь путь из ошибки сети. Время загрузки, retry и переход в приложение — продуктовая логика, не браузерные таймеры макета. Нельзя бесконечно утверждать, что пользователь входит, когда авторизация провалилась.
- Сохранять `prefers-reduced-motion`: без принудительной бесконечной анимации при пользовательском запрете движения.
- Не размещать Header и Dock на Welcome/Loader. Они возвращаются только после перехода к авторизованному интерфейсу.

## Статус

Разрешён для PR как **показанный владельцу UX-макет с исправленным текстом**; не интегрирован в `compat/assignment-release/` и не выполняет проверку настоящей сессии. Файл `standalone` сохранён неизменным. `index.html + style.css + app.js` текстово восстанавливают его. Нужна отдельная production-реализация и runtime validation.
