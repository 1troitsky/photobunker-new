## Принятый UI карточки

1. Публичная **веб-страница без логина и App Shell/Dock**, с минимальным Header: **логотип PhotoBunker** слева, компактная кнопка **«Установить приложение» со звездой/галочкой** справа. Нет обязательных элементов авторизованного интерфейса.
2. Название и `#NAME-ID` файла, рядом три контекстные иконки: **C — копировать ссылку; D — скачать; S — поделиться**. Не путать разрешение *посмотреть* с правом *скачать*.
3. Без навязанного фиксированного размера просмотра: фото по доступной ширине с сохранением пропорций, масштабирование по нажатию. Текущий HTML иллюстрирует фотографию встроенной графикой; интерфейс должен поддержать разрешённые фото/медиа по отдельному контракту (scopes видео/аудио пока не утверждены).
4. Затем разрешённое описание, **срок действия карточки / удаления исходного файла** (в т. ч. сколько дней осталось), **GPS и карта** только при разрешённом раскрытии координат, ссылка на карточку с копированием, дополнительные поля только если разрешены: дата съёмки, изменения, теги, автор/команда и разрешённый переход к публичному профилю.
5. **Футер:** «Опубликовано через PhotoBunker» со ссылкой на страницу установки и **`© 2026 PhotoBunker`**. Тёмный нейтральный Fieldwork, зелёный акцент, среднее скругление, адаптация к мобильному и desktop.
6. HTML позволяет в **панели предпросмотра** переключать четыре состояния `full / restricted / viewOnly / expired`: полные данные и GPS; скрытые поля; просмотр без скачивания; срок истёк. Переключатели **не входят в продуктовую публичную карточку** и не меняют серверные ACL. При expiry карточка не должна продолжать раскрывать media/metadata.
7. Просмотр безопасной версии не раскрывает оригинал: **никаких исходных фото/видео, реального EXIF/XMP, закрытых metadata или неконтролируемого GPS в публичной выдаче**. Скачивание (если разрешено) — разрешённая безопасная flatten-версия без EXIF, никогда original-by-default. Ключи, оригиналы и личные данные не передавать в браузер получателя.
8. Публичная карточка файла и **Browser Share нескольких файлов / целого задания** — разные scopes. Второй сценарий остаётся открытым в [SHARING-OPEN-QUESTIONS.md](../browser/SHARING-OPEN-QUESTIONS.md); принятие UI Public Card не санкционирует его реализацию.

## Установка PhotoBunker (экран по кнопке Header)

- Указанный пользователем адрес: **https://photobunker.mysite.net**. В HTML он выступает ссылкой установки; не считать факт развёртывания домена доказанным.
- **iPhone:** открыть адрес **именно в Safari** → «Поделиться» → «На экран „Домой“» → проверить включённый переключатель **«Открыть как веб-приложение»** → «Добавить».
- **Android:** открыть в **Google Chrome** → меню **⋮** → **«Установить приложение»** или **«Добавить на главный экран»**, в зависимости от версии и доступности установки.
- **Desktop:** Google Chrome → значок установки в адресной строке или соответствующий пункт меню браузера.
- В production определять платформу и предлагать только поддерживаемый способ установки; не обещать системного диалога, если PWA не соответствует installability/HTTPS/manifest/SW или браузер не поддерживает нужный сценарий. Не перенаправлять в App Store/Google Play как обязательный шаг.

## Обязательные границы безопасности и реализация

- **Два уровня настройки видимости:** Assignment Editor задаёт **потолок разрешённых публичных полей** (например, автор/команда, даты, GPS, описание, теги, metadata); Photo Editor управляет деталями **конкретного файла**. Итоговая проекция — только пересечение с действующими правами публикации/ссылки/типа media, а не копирование чекбоксов UI.
- Ссылка должна иметь отдельное подтверждённое право публикации/доступа, разрешённый безопасный asset и ограничение TTL: **card/share TTL ≤ TTL файла/задания**, revocation и смена ACL действуют и для уже известных ссылок; после expiry никакого возрождения старой публикации. Подробный протокол URL/token/key wrapping, scope, отзывы и аудит **пока не утверждены**.
- GPS-виджет с внешней картографией является отдельным раскрытием координат: не грузить стороннюю карту до подтверждённого разрешения и пользовательского действия. Текущий прототип использует OpenStreetMap как интерактивное действие, не как окончательно утверждённый контракт провайдера.
- Внешний просмотр без авторизации несовместим с прямым раскрытием E2EE original. Для safe-public версии нужна отдельная publish/derivative цепочка и серверная проверка прав на каждом запросе; не переносить клиентскую демо-логику доверия в production.
- Demo-URL `https://photobunker.example/p/SITE0001`, даты, автор, coordinates и файл — образцы из макета. **Это не реально опубликованные адреса или материалы**. Сам HTML не создаёт, не отзывает и не продаёт публичный доступ.
- Конфликтные/неутверждённые правила уточнять отдельно до production: политика публичного скачивания, набор media форматов, платный share за пределами PhotoBunker, срок ссылки, кто может создавать/отзывать ссылку, карты, разрешённые поля.
- Исходная спецификация File Viewer: [README](../browser/viewer/README.md); редактора фото: [README](../browser/editor/README.md); задания: [README](../assignments/editor/README.md); хранение/TTL: [03-PHOTO-STORAGE.md](../../03-PHOTO-STORAGE.md).
