## 1. Наследуемая композиция Photo Editor

Сохраняются Header **64 px** (логотип, статус под названием, текстовая «Отмена» и зелёная «Сохранить»), прозрачный breadcrumb **Browser › задание › файл**, заголовок **«Редактировать видео» / «Редактировать аудио»**, три вкладки **Информация / Видео или Аудио / Проверка**, прокручиваемый контент, нижние sheets и общий dock **82 px**: Задания / Browser / Камера / Контакты / Профиль.

Ниже медиасцены располагаются **Undo**, зеркальная нормальная стрелка **Redo**, текстовая **«Отменить изменения»**, а справа **«До / После»**. Внешний каркас не должен менять размеры между режимами.

## 2. Вкладка «Информация»

Повторяет структуру Photo Editor 3.2: **Название, Описание, GPS координаты, Категория и теги, Хранение и задание, Публичная карточка**. Теги — редактируемые чипы и выбор/добавление из одной панели; не превращать их в несколько постоянных полей.

Чекбокс продления хранения расположен **слева**, подпись **«До окончания действия тарифного плана»**. Приведённые в HTML даты/тарифы — пример интерфейса, не реальные ограничения. Смена задания, скрытие полей, доступ к оригиналу и права куратора в будущем должны подчиняться существующей доменной политике.

## 3. Вкладка «Видео»

- **Обрезка:** встроенное воспроизведение MP4; play/pause, seek, два ползунка **Начало / Конец**, длительность выделения, **«Просмотреть фрагмент»** и **«Применить обрезку»**. Undo/Redo, сброс правок, сравнение до/после. **В этой версии не создаётся новый MP4:** применяется только локальная граница просмотра.
- **Стоп-кадр:** перейти к нужному моменту, нажать **«Создать стоп-кадр»**; браузер получает JPEG через Canvas, показывает превью и время кадра. Стоп-кадр — **отдельный результат**, не изменение видеоряда.

После создания стоп-кадра доступны три пути:

1. **«Скачать JPEG на устройство»** — стандартная загрузка файла браузером.
2. **«В галерею устройства…»** — передача JPEG в системное меню через Web Share API, только при поддержке файлов браузером. Невозможно гарантировать, что пользователь выберет системную галерею; успешный вызов share **не означает**, что файл действительно сохранён в «Фото».
3. **«Сохранить в Browser»** — выбрать папку и добавить результат в локальную коллекцию самого **HTML-прототипа**. Эта коллекция пока **не синхронизируется с Browser v3** и не загружает файл в облако.

## 4. Вкладка «Аудио»

Воспроизведение M4A, звуковая дорожка, позиция, **Начало / Конец**, предпросмотр и применение границ. Действие **«Создать WAV-фрагмент»** декодирует доступный браузеру файл и создаёт новый **PCM 16-bit WAV** в текущем прототипе; для неподдерживаемых кодеков требуется понятная ошибка.

После создания WAV доступны три пути:

1. **«Сохранить WAV на устройство»** — обычное скачивание файла.
2. **«В медиатеку устройства…»** — передача WAV через системное меню файлов, **если поддерживается**. Веб-страница не может принудительно записать файл в музыкальную медиатеку ОС.
3. **«Сохранить в Browser»** — добавление в локальную коллекцию прототипа с выбором папки; в будущем нужно подключить существующий Browser v3 и его права.

Кнопки системной передачи **скрываются**, если браузер не сообщает поддержку Web Share файлов. Не показывать две фиктивно разные операции, если ОС не позволяет их разделить.

## 5. Локальная коллекция созданных файлов

Сохранение в Browser в автономном HTML использует **IndexedDB** с базой **fieldwork-file-editor-browser-v1**, хранилище **media**; при недоступности IndexedDB остаётся временное хранение **в памяти текущей вкладки**. Можно открыть список сохранённых результатов, скачать их или удалить. Эти записи **не появляются автоматически** в реальном Browser, API или зашифрованном хранилище, поскольку интеграции нет.

Скачивание через браузер не подтверждает запись в конкретной системной папке; Web Share возвращает управление из системного меню, но не гарантирует импорт в фотогалерею или музыкальную библиотеку. Не выводить фиктивный статус доставки в серверное хранилище.

## 6. «Проверка», сохранение и навигация

Сохранена **«Проверка куратором»**: «На рассмотрении», решения **Принять / Исправить / Переснять / Отклонить**, обязательный комментарий при исправлении, пересъёмке и отклонении, история. В HTML все решения локальные и не доказывают работу ACL или backend review.

«Сохранить» фиксирует локальные изменения полей и границ, «Отмена» подтверждает выход при незавершённых правках. Смена медиарежима для демонстрации не должна удалять черновики обоих редакторов.

## 7. Граница production и приёмка

**Утверждён только UX и его автономный frontend.** Не реализованы production MP4-экспорт, защищённое сохранение в Browser, E2EE, ключи, полноценный media outbox, TTL, синхронизация, подтверждённые публичные ссылки и системное сохранение напрямую в медиатеку ОС. Не копировать демонстрационную IndexedDB как альтернативу production-архитектуре; использовать существующие модели Browser/File Viewer, Local-First и права доступа.

Для фиксации в PR: сохранить исходный автономный HTML **без единого изменения**, разделить CSS и оба JS-фрагмента так, чтобы обратная сборка совпадала **точно** с источником; проверить JS-синтаксис и новые ссылки в UX-каталоге. **Повторный live browser/E2E и production-тест именно загруженного PR не заявлять**, если они отдельно не выполнены.

**Порядок последующих изменений:** отдельный frontend HTML → утверждение владельца → документация в PR. Ранее согласованные Browser v3, File Viewer 1.0, Photo Editor 3.2 и Camera не переписывать.
