**Источник истины — именно Browser v3**, принятая владельцем после нескольких итераций. Старое название Browser 3.1 относится к предыдущей редакции и не должно использоваться для определения поведения нового каталога. **Photo Viewer, Photo Editor и Camera — самостоятельные экраны; этот PR не меняет их исходники.**

## 2. Компоновка и файлы

- Header: слева квадратный логотип, название и статус «В работе» под ним; справа только **Новая папка / Загрузить файлы / Выбрать / Поиск / Настройки**. Кнопки — простые пиктограммы, не карточки. **Поделиться находится в меню объекта**, а не в Header v3.
- Заголовок **Browser**, число фото/файлов и папок под ним, переключатели **Сетка / Список / Дерево** справа. По умолчанию в макете открыт **список**.
- Вкладки **Все / Мои фото / Задания / Архив**; строка breadcrumbs с прозрачным фоном и стрелкой назад. При отключении архива соответствующая вкладка скрывается.
- Снизу фиксированный dock: **Задания / Browser / Камера / Контакты / Профиль**. Скролл не должен менять геометрию Header/dock.
- **Фото** отображаются миниатюрами; **видео — пиктограммой видеокамеры**, **аудио — музыкальными нотами**. В примерах присутствуют по два видео MP4 и аудио M4A. Примерные видео/аудио — элементы каталога, а не встроенные воспроизводимые медиафайлы.
- **Папки** показывают коллаж 2×2 из доступных медиа, с небольшой иконкой папки, без большой надписи «ПАПКА». В пустой папке — знак папки. В дереве папки раскрываются стрелками; во всех трёх видах у элементов присутствует кнопка действий **•••**.
- В списке/дереве метаданные остаются компактными: имя, дата, оставшееся время/дата удаления, разрешённые теги и категория. В production не раскрывать неразрешённую метаинформацию.

## 3. Создание папки

Кнопка **+** открывает нижнюю панель **Новая папка** с названием и выбором расположения. Предварительно выбрана **текущая открытая папка**. Разрешено создавать пользовательские папки непосредственно в корне **Все** и во вложенных папках; можно выбрать другое разрешённое расположение. Пустые и дублирующие имена в одном родителе отклоняются.

**Системные разделы и задания нельзя переименовать или удалить.** Пользовательские папки допускают действия в рамках полномочий. Создание в контексте задания в production требует фактических прав, а не доверия одному select-полю.

## 4. Загрузчик файлов

Отдельная иконка в шапке открывает одну bottom sheet:

1. **Папка назначения:** по умолчанию текущая открытая папка/корень, если в неё допустима запись; пользователь может выбрать другую папку, включая вложенные папки. Не заставлять заново разыскивать текущее расположение.
2. **С устройства:** фото, видео и аудио; множественный выбор, drag-and-drop.
3. **По ссылке:** прямая HTTPS-ссылка на файл. HTML делает запрос из браузера; источники с CORS, авторизацией или ссылкой на веб-страницу вместо файла могут быть недоступны.
4. В исходном UX указано «На вашем устройстве лимит 100 МБ на файл». Это **демонстрационный локальный предел**, не правило серверного тарифа. Текст не должен содержать посторонние комментарии об устройстве макета и не должен вставлять бренд в универсальное предупреждение.

Результат появляется в выбранной папке в UI, без обновления страницы. В демонстрации материалы существуют только в памяти вкладки: нет реального upload, E2EE, подтверждённого server commit, ACL или долговременной синхронизации. В production правила назначения, размер, сохранение и авторизация требуют отдельной реализации.

## 5. Поиск

Поисковая панель сочетает **текстовый запрос**, фильтр **Все файлы / Фото / Видео / Аудио** и явный выбор области: **текущая папка / выбранная папка / все папки**. При глобальном поиске видно расположение найденного файла. Прежние теги над поиском заменены **типами файлов** (теги остаются метаданными и доступны в действиях).

## 6. Меню и массовые действия

У каждого файла и папки в сетке, списке и дереве есть меню **•••**. Для файла в нём действие называется **Открыть файл**, а не «Открыть фотографию». Остальные применимые операции: **Поделиться, Переименовать, Изменить теги, Изменить категорию, В архив / Восстановить, Переместить, Удалить**. У системных папок и заданий нет запрещённых действий переименования и удаления. Реальный механизм обмена и scopes: [SHARING-OPEN-QUESTIONS.md](SHARING-OPEN-QUESTIONS.md).

Режим выбора: **Выбрано: N → Отмена → Действия**; **Выбрать всё** находится внутри меню действий. Для выбранных файлов доступны пакетные операции:

- **Теги:** **Добавить**, **Заменить все**, **Удалить указанные**; не изменять теги папок автоматически.
- **Категория:** назначить одну категорию сразу всем выбранным файлам. Подсказки берутся из уже существующих категорий.

Массовое перемещение, архивация и удаление доступны только в разрешённых контекстах; нельзя перемещать папку в саму себя/дочерние каталоги либо обходить права.

## 7. Настройки Browser

Сохранены **Открывать первым**, **Папки всегда сверху** и **Показывать оставшиеся дни**. Дополнительно приняты:

- **Использовать архив** — в демо включено по умолчанию. При включении удаление из обычной папки **перемещает файл в архив**; удаление уже архивного объекта окончательно. При отключении архив **скрывается**, удаление происходит **сразу**. Скрытие архива не должно само по себе уничтожать ранее архивированные объекты.
- **Автоудаление из архива через 7 дней** — отдельный переключатель, в демо включён. Срок отсчитывается с момента помещения в архив; при выключении автоматического удаления нет. В HTML очистка выполняется только периодически пока страница открыта: **не production TTL scheduler**.
- **Сортировка:** новые, старые, по названию, **по дате удаления (ближайшие первыми)**, **по дате изменения (недавно изменённые первыми)**. Элементы без срока не могут притворяться близкими к удалению.
- **Папки всегда сверху** определяет приоритет папок при сортировке, но не разрушает иерархию в режиме дерева; **оставшиеся дни** меняют только отображение, не сам TTL.

## 8. Граница работ и требования перед переносом

**Этот этап — только каталог.** Раздельные [Photo Viewer](viewer/README.md) и [Photo Editor](editor/README.md) остаются без изменений. Следующий UX-этап — File Viewer, который добавит видео/аудио просмотр, обрезку и стоп-кадр поверх уже принятого шаблона просмотра; в этом Browser v3 таких редакторов нет.

В production отдельно реализовать: защищённое хранение видео/аудио, Local-First/outbox, права на импорт в задания, E2EE, ограничения, TTL, архивный планировщик, синхронизацию, удаление, выдачу ссылок и аудит. HTML-демо не подтверждает работоспособность этих систем.

В текущем PR нужно проверить **эквивалентность разделённых файлов точному исходнику v3** и JavaScript-синтаксис. **Новый live browser/E2E-тест этой модульной версии не проведён в текущем окружении**; владелец принял исходный интерактивный HTML. Production-сборка и тесты реальных устройств — отдельно.

**Правило следующей итерации:** сначала показать новый фронтенд отдельно, дождаться явного утверждения владельца, лишь затем обновлять PR. Не использовать прежний Browser 3.1 для замены принятого v3.
