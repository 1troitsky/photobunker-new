# Browser — Fieldwork 3.1 · OWNER-SELECTED UX

**Тип:** самостоятельный frontend-эталон с демоданными, **НЕ рабочая реализация Browser**. Выбранный владельцем стиль: Fieldwork / Spotify-inspired dark. Утверждены упрощения после версий 1–3 и добавление иконки «Поделиться» в шапку.

## Как посмотреть

Из корня проекта: `python3 -m http.server 8080`, затем `http://localhost:8080/docs/ux/browser/`.

| Файл | Назначение |
| --- | --- |
| [`index.html`](index.html) | Разметка, единая шапка/контент/dock, режимы, path bar, иконка «Поделиться» |
| [`style.css`](style.css) | Только Browser-специфичные стили, повторно использует `../assignments/style.css` |
| [`app.js`](app.js) | Интерактивное demo-состояние (вкладки, папки, коллажи, навигация, поиск, выбор, сортировка, настройки, actions) |
| [`SHARING-OPEN-QUESTIONS.md`](SHARING-OPEN-QUESTIONS.md) | Нерешённый контракт обмена фотографией и целым заданием: **НЕ реализовывать до продуктового решения** |

Имена, лица и фото отсутствуют: изображения — **абстрактные SVG-заглушки**. Данные только локальные в памяти страницы, исчезают после перезагрузки. В Browser прототипе нет реальных API, криптографии, сохранения, удаления в storage, ссылок и отправки.

## Зафиксированный дизайн (не переделывать самовольно)

1. **Shell:** Header `[pb] PhotoBunker`, под именем системный статус; справа только bare-icon кнопки **Новая папка / Выбрать / Поделиться / Поиск / Настройки**. Без рамок вокруг кнопок; границы есть только у самих полей. Контент прокручивается отдельно, dock высотой 82px закреплён снизу. Header/dock — общие с Assignments и будущими экранами. **Текущие 5 навигационных пунктов:** Задания, Browser, Камера, Контакты, Профиль.
2. **Название:** `Browser` слева, прямо **под ним очень мелко** количество фото и папок текущего расположения. **Справа от заголовка** компактные иконки-переключатели **Сетка / Список / Дерево**. Не повторять эту группу ниже, не делать отдельную панель «N элементов» над списком.
3. **Разделы:** Все / Мои фото / Задания / Архив. Назначение каждого без изменений относительно `ts_and_ux.md` и `PhotoBrowserIndexView.vue`.
4. **Path bar всегда виден** сразу под вкладками. Слева стрелка **назад на уровень выше**, справа горизонтальный breadcrumb `Все › Мои фото › Папка`. **Никаких обводок, карточек и фона** у path bar. Переходы по крошкам работают; длинные имена сокращать, сохранять точный адрес/маршрут и возможность вернуться.
5. **Сетка:** фотографии — **одно большое превью**, папки/задания/разделы — **2×2 коллаж из первых четырёх доступных превью вложенных фотографий**, поверх коллажа маленькая метка/иконка папки. Пустая папка — иконка папки, НЕ нарисованный коллаж. В коллаже не раскрывать непросматриваемые изображения/метаданные. В макете используется схематичная иллюстрация, production должен повторно использовать существующий `PhotoThumbnail`, access-key/expiry, и только доступные `cover(entry)`.
6. **Список / Дерево:** компактные строки с миниатюрой; **не показывать ярлыки «ФОТО» или «ПАПКА»**. Tree: реальная вложенность и раскрытие, без выдуманных папок/изменения структуры. Для фото: ID/имя, дата, удаление/остаток дней, разрешённые теги. Для папок: название, количество вложенных фото, дата если известна.
7. **Поиск:** по ID/имени/разрешённым тегам, контекстный; поиск не должен обойти ACL, утечку метаданных или ограничения thumbnail-only.
8. **Режим выбора:** только `Выбрано: N` → **`Отмена`** → **`Действия`**. Команда **`Выбрать всё`** живёт внутри меню «Действия», в основной панели её нет. Внутри доступны разрешённые действия согласно текущим правам; никаких несанкционированных массовых операций.
9. **Настройки:** начальный раздел, сортировка (новые/старые/название) и **два новых переключателя:**
   - **«Папки всегда сверху»**: по умолчанию в макете `true`; выключение даёт общую сортировку элементов без отдельного приоритета папок. В режиме дерева сортировать **по уровню**, не перемешивая родительские и дочерние узлы.
   - **«Показывать оставшиеся дни»**: в макете по умолчанию `false`; вместо `Удаление: 20 ноя` — `Осталось: 13 дней`. Реальный расчёт — из `expiresAt` и актуального времени, без продления TTL; обрабатывать истечение, timezone и отсутствие срока. Настройка **только представления**, НЕ меняет TTL и не влияет на удаление.
   - Production-сохранение пользовательских настроек должно соответствовать существующему Browser settings и Local-First подходу; демоверсия ничего не сохраняет.
10. **Поделиться в шапке:** новая **иконка Share без обводки**, рядом с другими действиями. На прототипе открывает поясняющую панель (фото / задание), **не создаёт реальную ссылку и не предоставляет права**. Цель: дать ясную точку входа для обмена. **Делиться целым заданием со всеми доступными фото — желаемая функция, механизм и политики открыты: см. SHARING-OPEN-QUESTIONS.md.** Это не «Временная подборка» и не её автоматическая замена.
11. **Не добавлять ненужные функции.** В текущий утверждённый Browser **не входят панели создания временных коллекций, экспорт-центра, маркетинговые блоки, дополнительные навигации**. При переносе в production нельзя молча удалять уже существующую функцию Temporary Browser Collection: она реализована сейчас, но исключена **из этого прототипа**. Решение о месте/судьбе отдельное.

Иконка «Поделиться заданием» — **только UI и зафиксированная идея**, не permission grant. Если backend/модель не предусматривает сохранение новых настроек, оформить отдельную задачу, не добавлять произвольные поля в схемы.

## Правила для агента при будущем переносе

- Не менять `main`, Vue runtime, core-модель, crypto, permission boundary, Photo Card, TTL, storage и server API в этом PR. Эталон живёт **только** в `docs/ux/browser/`.
- Не подменять существующие `ExplorerEntry`, `buildExplorer`, `explorerRows`, `canMove`, `PhotoThumbnail`, `PublicCardLink`, authorizations, cache и sync демо-функциями.
- Учитывать `entry.readable/editable/deletable/shareable`, `thumbnailOnly`, `archived`, `workspaceAccess`, `scope`; заблокированные данные не раскрывать через поиск, превью, теги, подборки, статус или меню.
- Реальные action sheets оставить функциональными; `Back` должен учитывать браузерную историю и вложенность, не терять state при переключениях; локально заполненный контент показывать немедленно (Local-First), сетевые ошибки отдельно.
- Реальную совместимость iOS PWA, desktop, narrow screens, scrolling, safe-area, offline/online, selection, expiry и доступность клавиатуры принимать **на настоящем приложении**, а не по демо.
- **Запрещено** строить новую публикацию/шаринг/экспорт задания, ссылку, новые серверные endpoints, новый ACL или выдачу ключей **без отдельного решения владельца** по документу `SHARING-OPEN-QUESTIONS.md`.
- После переноса сравнить production с прототипом: внешний вид, группировку, последовательность кнопок и все состояния. Статус до проверки: `DESIGN APPROVED / IMPLEMENTATION NOT STARTED`.

## Краткие проверочные сценарии

1. При открытии: раздел «Мои фото», заголовок Browser; под ним фото+папки, справа смена вида; путь **без рамки/фона**.
2. В Grid: папка с четырьмя миниатюрами и иконкой папки, фотография с одним превью. Пустая папка с fallback-значком.
3. Открыть `Мои фото → Городские прогулки`, вернуться стрелкой и крошками, затем `Задания → Фасады — Site A → Детали фасада`.
4. Переключить Grid → List → Tree: в List/Tree нет бейджей «ПАПКА»/«ФОТО», дерево раскрывается.
5. Включить «Выбрать», выделить файлы: `Выбрано: N / Отмена / Действия`. Внутри «Действия» есть «Выбрать всё».
6. Сортировать с `foldersFirst` включённым и выключенным: порядок меняется, права/иерархия не меняются.
7. Переключить `daysLeft`: дата удаления заменяется на количество оставшихся дней, при этом TTL не меняется.
8. Нажать иконку «Поделиться» в шапке: только модальная демонстрация, **нет ссылки, нет API, нет grant**.
9. Поиск/теги, пустые разделы, no rights, истекшие фото и offline проверить позже в production на реальном сценарии.
