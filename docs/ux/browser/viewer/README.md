# Photo Viewer — Fieldwork 3.1 · OWNER-APPROVED UX

**Статус:** выбранный владельцем UX и frontend-эталон, **НЕ production implementation**.

Дата согласования: 2026-11-07. Сам Photo Viewer — часть **Browser**, а не отдельная мини-программа со своей шапкой и доком.

## Запуск и состав

Из корня репозитория:

```sh
python3 -m http.server 8080
```

Открыть `http://localhost:8080/docs/ux/browser/viewer/`.

- [`index.html`](index.html) — согласованная иерархия и общая оболочка.
- [`style.css`](style.css) — **только отличающиеся стили Photo Viewer**; сначала импортируются `../../assignments/style.css` и `../style.css`. Не копировать стили Header/dock в каждый экран.
- [`app.js`](app.js) — интерактивное демо: 4 вымышленные фотографии разной ориентации, жесты, кнопки, журнал статусов и нижние панели.
- [`../../UI-SHELL-CONTRACT.md`](../../UI-SHELL-CONTRACT.md) — **обязательный контракт Header + dock для всех экранов**, читать перед любыми изменениями.

Нет реальных фотографий, аккаунтов, API, key-sharing, изменений TTL, ссылок, сохранённых настроек или операций с сервером. Сжатый файл и буфер обмена содержат лишь нарисованный в макете SVG, преобразованный в растр. Изменение демоданных исчезает после перезагрузки.

## Готовая композиция экрана — точный порядок

1. **Header — неизменный глобальный каркас:** `[pb] PhotoBunker`, под названием — системный статус. Контекстные bare-icon кнопки для Photo Viewer строго в порядке **Избранное / Копировать / Скачать / Удалить**. Размеры, цветовая схема, положения бренда и статуса совпадают с Assignments и Browser. Не добавлять назад в Header: она в path bar.
2. **Path bar, идентичный Browser:** простой `← Все › Задания › Фасады — Site A › Детали фасада`, **без рамки и фона**, сразу под Header. Возврат на уровень выше, переходы по хлебным крошкам; производственный роутер обязан сохранять контекст Browser.
3. **Фото:** фиксированная по доступному пространству область с `object-fit: contain` / эквивалентом. Смена фото между горизонтальной и вертикальной ориентацией **НЕ двигает** Header, path bar, описание, действия, листатель и dock. Изображение не обрезать.
4. **Метаданные под фото:** **название жирное**, рядом тонкий маленький `NAME-ID`; описание **не более двух строк, многоточие**; создано и дата удаления с **количеством оставшихся дней**. Полный текст описания не обрезать в окне «Информация».
5. **Три равноправные кнопки:** Информация / Публичная карточка / Редактировать.
6. **Листатель** непосредственно под кнопками: стрелка влево, `текущий / всего`, стрелка вправо.
7. **Dock** всегда общий — **Задания / Browser / Камера / Контакты / Профиль**, высота 82px, активный Browser.

CSS геометрия фиксированного просмотра: `grid-template-rows: 45px minmax(0,1fr) 114px 57px 48px`, dock и Header — из общего CSS. Пользователь утвердил именно принцип: фото меняет размер *внутри* выделенной области, а не её высоту.

## Управление и анимация (ОБЯЗАТЕЛЬНО)

| Ввод | Действие | Важные условия |
| --- | --- | --- |
| Свайп **влево** в зоне фото | Следующая фотография | Не изменяет фиксированные блоки; на последнем снимке остаётся текущий |
| Свайп **вправо** в зоне фото | Предыдущая фотография | Не изменяет фиксированные блоки; на первом снимке остаётся текущий |
| Свайп влево/вправо **в fullscreen** | То же перелистывание | Fullscreen не закрывается при горизонтальном свайпе |
| Свайп **вверх** в fullscreen | Закрыть fullscreen, направленная анимация вверх | Возврат к **тому же** снимку и месту в Browser |
| Свайп **вниз** в fullscreen | Закрыть fullscreen, направленная анимация вниз | То же; не менять листатель и роут |
| Tap по фотографии | Открыть fullscreen | Не обрабатывать завершающий `click` горизонтального свайпа как tap |
| `×` / `Escape` в fullscreen | Закрыть | Можно использовать кнопку и клавиатуру |
| Стрелки в листателе и `ArrowLeft` / `ArrowRight` (без фокуса в input) | Перелистывание | Клавиатура не перелистывает фото, пока открыт sheet, download popover или In-App Browser |
| Нажатие «Информация» или «Редактировать» | **Плавный bottom sheet** | Выезжает снизу, фон слегка затемняется, закрывается кнопкой, backdrop или Escape |
| Нажатие «Публичная карточка» | **In-App Browser** поверх экрана | Темные верхняя и нижняя панели браузера, «Готово», на закрытии возврат к фото |

Прототип использует `Pointer Events` с порогами **60px** по горизонтали и **86px** по вертикали в fullscreen и проверкой доминирующей оси (примерно 1.25). Это **демо-ориентиры**, а не навязанные production константы. Production проверить на реальных iOS/Android, включая `pointercancel`, мультитач и системные жесты. Горизонтальные движения **не должны ломать вертикальную прокрутку**, меню действий, редактирование и native browser navigation. Никаких жестов на общем Dock, Header и форме.

Анимация смены фото — направленная, плавная, короткая, без перестроения layout (например, лёгкий `translateX + opacity`); нижняя панель — `translateY` с easing, fullscreen уезжает **по направлению вертикального жеста**. Начало/конец жеста должно быть предсказуемым; при маленьком/прерванном жесте возврат в исходное состояние. **`prefers-reduced-motion: reduce` обязателен**: минимальные/отключенные анимации при сохранении функциональности.

**ЗАПРЕТ:** повторно строить viewer вокруг картинки с динамической высотой, переносить стрелки в шапку, скрывать fixed dock или превращать вертикальные свайпы в перелистывание.

## Header: обязательные действия

- **Избранное.** Звезда полностью закрашена зеленым, когда фото в избранном. Новое решение для будущей production-реализации: в Browser автоматически появляется **папка/виртуальный раздел «Избранное»**, если его ещё нет. Не создавать настоящую файловую папку без согласования модели хранения; не делать дубликат фото.
- **Копировать.** Копируется **сжатая безопасная версия**, а **не оригинал**. API может требовать PNG для clipboard (в демо именно так), но исходник/EXIF/GPS не допускаются в передаваемый файл без отдельных разрешений. Любая ошибка — в системном статусе.
- **Скачать.** По первому нажатию под иконкой — небольшой popover с вопросом **«Скачать фотографию?»** и текстом **«Вы уверены, что хотите скачать фотографию на свое устройство?»**, кнопки **Отмена / Скачать**. Только второе нажатие запускает подготовку. Пока идёт операция: спиннер и **«Подготовка сжатого JPEG для скачивания»**. По завершении открыть **доступный системный механизм сохранения** (где браузер не поддерживает native Share — обычное сохранение через download). Нельзя делать вид, что файл сохранён, когда лишь открыто системное меню.
- **Удалить.** Только при явном разрешении и подтверждении; ошибки — в журнале статусов. Не вызывать удаление storage/key в UI-прототипе.

**Не путать** обычное действие «Скачать сжатую копию» с отдельным доступом к оригиналу. Любая production операция должна проходить проверки существующего permission / photo-scope контракта.

## Bottom sheet: читаемость — обязательна

**Информация:** ПЕРВЫМ отображается крупный, хорошо читаемый блок **«Полное описание»**, текст полностью, без `line-clamp`, на графитовой подложке с ярким текстом. **Затем** метаданные (ID, название, задание, папка, автор, категория, дата, срок, размер, разрешённые GPS-данные и пр.). Не допускать black-on-black, наложений и ошибки z-index. Метаданные отображать лишь при действующих разрешениях.

**Редактировать:** такой же плавный нижний sheet. В demo правятся название и описание, production вызывает существующий **полноценный** редактор; не подменять настоящую editing-модель демонстрационным обработчиком.

**Public Card / Публичная карточка:** визуально похожа на приложенный владельцем пример Safari-подобного In-App Browser. **Тёмные элементы самого браузера PhotoBunker** (верхняя панель, URL/лейбл, нижняя панель, кнопка «Готово»). **Веб-содержимое** может быть светлым или тёмным независимо от системных панелей. Сейчас в прототипе показана демо-страница, а не подгруженная публичная ссылка. В production использовать существующие `PublicCardLink`, `PhotoCardView.vue`/маршруты, политики доступности и решение владельца о реальном браузерном контейнере — не создавать публичную ссылку по самому факту открытия экрана.

## Статус и журнал

Статус в общей шапке открывает журнал текущей операции, предупреждений, ошибок (копирование/скачивание/удаление/связь), включая предыдущие записи. Это продуктовый UI-контракт; в демо журнал хранится только в памяти. Операционные статусы и подтверждения не выдумывать: `navigator.share()` мог быть отменён; browser download нельзя считать доказательством успешного сохранения; Local-First optimistic UI не заменяет серверные подтверждения для необратимых действий. Для production требуется **централизованный** status store, а не отдельный массив на странице.

## Проверить перед интеграцией в Vue

Основные источники: `compat/assignment-release/apps/web/src/views/PhotoView.vue`, `compat/assignment-release/apps/web/src/styles/photo-viewer.css`, `compat/assignment-release/apps/web/src/views/PhotoCardView.vue`, `ts_and_ux.md`, `docs/ux/browser/README.md`.

1. Прочитать `AGENTS.md` и `CHATBOT-AGENTS.md`. Сверить **актуальные** `main` и действующие маршруты до изменения production.
2. Сохранить существующий `minmax(0,1fr)`, доступ к версиям, blob lifecycle, fullscreen, фото-ACL, TTL и фоторедактор. Внешний вид — заменить только внутри разрешённой поверхности, не внедрять фронтенд demo напрямую.
3. Проверить портретный кадр после горизонтального: **никаких скачков геометрии**. Тестировать реальную клавиатуру, свайпы всех направлений, отскок коротких движений, конец списка, `Escape`, `prefers-reduced-motion`.
4. Проверить на телефоне/desktop, Safari iOS PWA, Chrome Android. Загрузки и буфер обмена — **реальные permissions**, правильно разделённые safe JPEG, compressed PNG и original.
5. Header/dock сравнить с `docs/ux/browser/index.html`, **ни одной визуально новой версии Shell**.
6. Полное описание — в начале Information, с контрастом; popover «Скачать?» — читаем; темный app browser chrome и page отдельно.
7. Реальные системные ошибки добавлять в центральный статус, без немого fallback и с сохранением контекста.
8. Архитектурное решение об избранном и возможности поделиться целым заданием — записать отдельно; **без новых backend/API/ACL схем в этом PR**.

**Состояние кода:** interactive demo with synthetic data; syntactic checks are possible, но отсутствие отчёта браузерного E2E не считать успешным E2E. Будущая production реализация — отдельная работа после принятия эталона.
