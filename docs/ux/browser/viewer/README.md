# File Viewer 1.0 — единый просмотр фото, видео и аудио

**Статус: OWNER-ACCEPTED UX / FRONTEND PROTOTYPE ONLY.** Владелец согласовал File Viewer 1.0 и поручил добавить его в Draft PR #56 7 ноября 2026 года. Это продолжение ранее утверждённого Photo Viewer 3.1, **не production-реализация**.

File Viewer остаётся **частью Browser**, а не отдельным приложением. Исторические файлы Photo Viewer 3.1 доступны в истории Git; текущий дизайн-эталон — File Viewer 1.0. Отдельный Photo Editor 3.2 Fixed и Browser v3 при этом не перерабатываются.

## 1. Неподвижная геометрия

**Ключевое утверждённое требование:** при переходах **фото → видео → аудио → фото** весь интерфейс остаётся на одном месте, без скачков высот, перестройки кнопок или перемещения шапки и dock.

Сохранены значения из Photo Viewer 3.1:

| Участок | Размер |
| --- | --- |
| Общая шапка (Header) | **64 px** |
| Путь Browser (breadcrumbs) | **45 px** |
| Универсальная область медиа | **minmax(0, 1fr)** — всё оставшееся пространство |
| Информация (название, описание, даты) | **114 px** |
| Три действия | **57 px** |
| Перелистывание | **48 px** |
| Общий нижний dock | **82 px** |

CSS: `grid-template-rows: 45px minmax(0,1fr) 114px 57px 48px`. Вся разница между медиа живёт **внутри единой области**, не меняя её размеры. Не превращать video controls или waveform в отдельную строку сетки и не растягивать блок описания длинным текстом. В режиме Desktop сохраняется та же структура блоков. При нехватке места медиа масштабируется **внутри** области, а не вытесняет другие элементы.

## 2. Единая оболочка и навигация

- Header: логотип [pb], имя приложения, статус под именем; справа **Избранное / Копировать / Скачать / Удалить**. Иконки, размеры и последовательность как в исходном Photo Viewer, а действия контекстно зависят от типа файла.
- Breadcrumbs: прозрачная строка с возвратом в папку Browser, стрелкой и путём. Реальный Browser должен восстанавливать **папку, фильтр, позицию и историю навигации**. В автономном макете переход — демонстрационный.
- Информационная полоса: **название, NAME-ID, краткое описание, дата создания и срок удаления**; полная информация находится в нижней панели.
- Ряд действий неизменен: **Информация / Публичная карточка / Редактировать**. Информация и карточка открываются внутри прежних модальных слоёв.
- Пейджер: **назад / N из всех файлов / вперёд**, последовательность смешанная (фото, видео, аудио).
- Dock: **Задания / Browser (активен) / Камера / Контакты / Профиль**; fixed 82 px.
- Фото может открываться в fullscreen, горизонтальный свайп перелистывает, вертикальный закрывает. В полноэкранном просмотре видео и аудио доступны те же типовые медиаконтролы; жесты не должны перехватывать нажатия по кнопкам, ползункам и плеерам. `prefers-reduced-motion` учитывается.

## 3. Медиа и примеры

В принятом HTML **семь** демонстрационных элементов в последовательности:

1. Фото — фасад (горизонтальное).
2. Видео — обход фасада (MP4, 4 секунды).
3. Аудио — звуки у здания (M4A, 8 секунд).
4. Фото — вертикальная арка.
5. Видео — прогулка вдоль фасада (MP4).
6. Аудио — комментарий к съёмке (M4A).
7. Фото — улица и боковой фасад.

Фотографии в демо являются SVG-иллюстрациями, видео/аудио встроены как `data:` URL. **Не считать демонстрационные параметры реальными атрибутами загруженных файлов.**

**Фото:** адаптивное изображение в универсальной сцене, full screen, копирование изображения в допустимых браузерах, скачивание JPEG (демо). Согласованный полноценный [Photo Editor 3.2 Fixed](../editor/README.md) остаётся отдельным экраном; внутри File Viewer доступен только упрощённый редактор названия/описания и сообщение о самостоятельном фоторедакторе.

**Видео:** HTML video controls (play/pause, seek, fullscreen), дополнительная кнопка общего fullscreen, плавный переход к следующему элементу. В редакторе: **Начало / Конец**, предпросмотр выбранного отрезка, применение границ и **«Создать стоп-кадр»**. Стоп-кадр — отдельная фотография, вставляется в список после видео; захват текущей позиции выполняется через video + Canvas. **Применение границ не создаёт перекодированный MP4**, оно сохраняет интервал только в локальном состоянии и ограничивает проигрывание.

**Аудио:** встроенный M4A-плеер, кнопка play/pause, ползунок позиции и декоративная волновая дорожка, остающиеся внутри той же медиаобласти. Редактор: **Начало / Конец**, предпросмотр и применение границ; действие **«Сохранить обрезанное аудио»** декодирует пример и формирует отдельный WAV (PCM 16 bit), добавляемый следующим элементом в локальный список. Это **не серверный media pipeline**, не гарантируется поддержка всех кодеков каждым браузером.

**Переключение файлов:** текущие аудио/видео останавливаются при переходе, объект нового типа занимает **ту же сцену**. Нельзя оставлять фоновой звук прежнего файла при листании или создавать независимые панели, меняющие верстку.

## 4. Действия и безопасность

- **Избранное:** зелёная закрашенная звезда для отмеченного файла. Коллекция «Избранное» не должна копировать содержимое и порождать новые ключи. Доменная модель коллекции остаётся отдельным вопросом.
- **Копировать:** для фото — растровую копию; для видео — стоп-кадр; для аудио действие неактивно. Фактическая поддержка Clipboard зависит от браузера/разрешений.
- **Скачать:** подтверждение в прежнем popover под иконкой; настоящие форматы и scope доступа должны определяться политикой файла, не подменяться JPEG. В демо запускается локальное скачивание.
- **Удалить:** отдельное подтверждение; реальная операция в production должна следовать принятому для Browser v3 режиму архива, ролям и retention/TTL. **Демо не реализует настоящее удаление из хранилища**.
- **Информация:** full description **перед** метаданными, затем NAME-ID, тип, формат, категория, автор, создание/удаление и, когда доступны, разрешение, длительность, выбранный фрагмент.
- **Публичная карточка:** автономный In-App Browser — предпросмотр, не опубликованная ссылка. Не расширять Public Card scopes для видео и аудио по умолчанию; потребуется отдельное решение о доступных версиях/полях.
- **Редактирование:** для видео/аудио — минимальный trim, для видео — frame; для фото — самостоятельный Photo Editor. Все действия требуют прав в production.

## 5. Где проходит граница прототипа

Исходник содержит UI, медиа-примеры и локальные операции в памяти вкладки. Он **не** обеспечивает: загрузку с сервера, E2EE media storage, encrypted outbox, управление ключами, Local-First persistence, аудит, проверку разрешений, транскодирование или физическое удаление из облака. Открытие public preview **не означает**, что ссылка создана.

Для будущей production-реализации отдельно нужны:

- Модель файлов с корректным MIME, длительностью, размерами, превью, категориями и ограничениями задания, с общим каталогом Browser v3.
- Выдача безопасных версий, реальные photo/video/audio scopes, запрет утечек оригинала и EXIF, права на скачивание и обмен.
- Надёжные encrypted cache/outbox и медиапайплайн (обрезка/экспорт/стоп-кадры), особенно для больших файлов и мобильного Safari.
- Поведение при ошибке декодирования/потока, смене вкладки, offline/reload, без неожиданной потери данных и без ложного уведомления об успешном серверном сохранении.
- Соблюдение настроек архивирования и TTL Browser v3 при удалении файлов.

## 6. Проверка при фиксации в PR

- Сохранить **без правок** автономный принятый HTML File Viewer 1.0, включая встроенные MP4/M4A.
- Разделённые `index.html`, `style.css`, `app.js` должны при обратной сборке **в точности совпадать** с оригинальным HTML.
- Проверить синтаксис JavaScript, фиксированные значения сетки и отсутствие модификаций в Browser v3 / Photo Editor / Camera.
- Пользователь уже видел и согласовал исходный интерактивный экран; **новая production/мобильная проверка этой фиксации не проводилась**. Не выдавать это за подтверждённую production-реализацию.

**Дальнейший порядок:** сначала отдельный HTML и утверждение владельца, потом PR. Следующие правки File Viewer не должны незаметно изменять уже утверждённый Browser v3.
