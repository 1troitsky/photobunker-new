# Photo Editor — Fieldwork 3.2 Fixed · выбранный UX-эталон

**Статус:** OWNER-SELECTED DESIGN / PROTOTYPE DOCUMENTED / **NOT PRODUCTION IMPLEMENTATION**. Дата последней итерации: 2026-11-07.

Этот экран является частью **Browser → Photo Viewer → Редактировать**. Источник — согласованный интерактивный HTML-макет «PhotoBunker — Photo Editor 3.2 Fixed» и изображение трёх состояний (Information, Photo Editor / Text, Curator Review), предоставленные владельцем. Внутри PR #56 хранится **точная визуальная версия 3.2**, разбитая на файлы для удобного просмотра; никаких действующих Vue-компонентов, API, криптографии, БД, TTL или прав доступа этот PR не изменяет.

## Файлы и предпросмотр

- [index.html](index.html) — экран, три вкладки, формы и интерактивные области.
- [style.css](style.css) — CSS исходного макета 3.2 (выделен из исходного HTML без намеренного редизайна).
- [app.js](app.js) — логика демонстрационных взаимодействий (выделена из исходного HTML).
- [UI Shell Contract](../../UI-SHELL-CONTRACT.md) — **нормативные** единые Header, статус и dock для переноса в production.
- [Browser](../README.md) и [Photo Viewer](../viewer/README.md) — источник навигационного контекста и входной точки.

Запуск из корня репозитория:

~~~sh
python3 -m http.server 8080
~~~

Открыть **http://localhost:8080/docs/ux/browser/editor/**. Встроенный переключатель **Телефон / Desktop** служит демонстрацией адаптивности. Реальные фото и приватные данные не используются. Никаких сетевых вызовов и постоянного сохранения нет.

**Важное различие:** полнофункциональный frontend-макет не равен production-фоторедактору. Технические детали композитинга изображения, выдачи файла и политики требуют отдельной реализации и проверки.

## 1. Общая композиция и переходы

1. **Header**: квадратная марка [pb], PhotoBunker и зелёный индикатор со статусом **«В работе» под названием**; справа текстовая **«Отмена»** и зелёная кнопка **«Сохранить» с иконкой дискетки**. Кнопка Save неактивна, пока нет изменений. Не заменять отмену иконкой.
2. **Path bar Browser**: стрелка назад и хлебные крошки **Browser › Фасады — Site A › SITE0001**. Строка прозрачная, без карточек и рамок, и не создаёт новую навигационную оболочку.
3. **Заголовок**: только **«Редактировать фото»**; не добавлять отдельную строку «Главный фасад · SITE0001» под названием.
4. **Три вкладки**: **Информация / Фото / Проверка**. Только содержимое между шапкой и доком прокручивается; при смене вкладки прокрутка возвращается вверх.
5. **Постоянный dock 82px**: Задания / Browser (активен) / Камера / Контакты / Профиль. Тёмный фон, приглушённые неактивные и зелёные активные иконка/название.
6. **Состояния и панели**: системный статус открывает журнал сообщений; диалоги подтверждения, теги и GPS-карта появляются как плавные bottom sheets поверх экрана. Закрытие — крестик, backdrop, Escape. Поддерживать reduced motion.

**Не переизобретать Shell:** в исходном автономном HTML стили шапки и дока находятся в локальном CSS, чтобы открыть файл без зависимостей. Это способ хранения макета, **не разрешение копировать Shell в production**. При внедрении использовать один общий компонент и store статуса из UI-SHELL-CONTRACT.md.

## 2. «Информация»

### 2.1. Основные поля

- **Название** — текст (обязателен), в демонстрации «Главный фасад», ограничение макета 120 символов.
- **Описание** — многострочный текст, изменяемый в форме.
- **GPS координаты** — ввод широта, долгота через запятую; кнопка карты справа открывает лист «Уточнить местоположение». На демонстрационной карте с закреплённой меткой можно сдвигать поверхность и применять показанные координаты.
- **Категория** — одиночный выбор из демонстрационных вариантов «Фасад», «Детали», «Интерьер», «Документация», «Другое».
- **Теги** — компактные зелёные чипы: нажатие по имени редактирует тег, × удаляет; кнопка **«Добавить / выбрать тег»** открывает общий выбор существующих тегов и поле нового тега. **Сохранить ранее согласованный UX тегов**; не размещать дополнительные поля «Новый тег / Добавить» в основной панели информации. Ограничение демо: до 30 тегов, уникальность без учёта регистра.

### 2.2. Хранение и принадлежность заданию

- **Дата удаления** редактируется в пределах разрешённого периода. **07.11.2026—20.12.2026 в макете — демонстрационные даты**, а не вечная граница продукта.
- Чекбокс **слева**: **«Автоматически продлевать срок хранения фотографии»**. Подзаголовок строго **«До окончания действия тарифного плана»**. Реальное продление допустимо только в пределах политик назначения, разрешений и оплаченного плана; UI не создаёт право на продление.
- Подсказка показывает максимально допустимую дату и ссылку **«изменить/продлить тариф»** — в демо ссылка открывает заглушку.
- **Задание** — выбор задания или «Без задания (личное фото)»; смена задания меняет папку фотографии и требует права **владельца задания и фотографии**, явного предупреждения и подтверждения. В frontend-макете это только смена поля.

### 2.3. Публичная карточка

- Переключатель **«Разрешить просмотр / Public Card»** управляет зависимой группой настроек. При выключении опции становятся недоступны, но настройка сама по себе **не выдаёт** публичный доступ.
- Поля: **Дата добавления, Дата изменения, GPS координаты, Описание, Теги, Метаданные**.
- Предустановки демонстрации: просмотр **включён**; **Дата добавления, Описание, Теги — включены**, **Дата изменения, GPS, Метаданные — выключены**.
- **Правила задания и фактические ACL/photo scopes всегда сильнее переключателей.** При переносе сверить модель Public Card, запреты на EXIF/координаты и существующий механизм безопасной версии изображения. Не расширять scope только по видимому чекбоксу.

## 3. «Фото» — пять инструментов

Перед рабочей областью — предупреждение **только для случая, когда правила задания не сохраняют оригинал**: «По правилам задания оригинал не сохраняется, поэтому после сохранения изменения нельзя будет отменить». В полноценном продукте видимость и точный текст зависят от реальной политики оригинала, а не от постоянной строки.

**Рабочая область:** изображение на чёрной сцене; сверху слой рисования/фигур и слой подписей. Под изображением: **Undo**, **Redo**, текстовая кнопка **«Отменить изменения»**, а справа **«До / После»**. Отмена через Undo/Redo относится к локальной истории обработки снимка; это **не отмена серверного сохранения**. «Отменить изменения» возвращает изображение к последней сохранённой версии, не очищая поля информации.

### 3.1. Кадр

- **Пропорции**: Исходные / 1:1 / 4:3 / 16:9.
- **Поворот**: −90° / текущий угол / +90°; изменение видно до сохранения.
- Production должен корректно выполнять реальные поворот и кадрирование растра; перестановка CSS-пропорций в demo не является готовым crop алгоритмом.

### 3.2. Цвет

Три ползунка с числовыми индикаторами: **Яркость / Контраст / Насыщенность**, начальные 100%, в demo диапазон 0–200%. Применение немедленно отражается в предпросмотре и попадает в локальную историю изменений. В production композитинг применяется ко всему требуемому output-слою по принятой модели, а не только к SVG-превью.

### 3.3. Рисовать

- **Кисть / Карандаш / Ластик**, отдельные кнопки с иконками.
- Ниже в одной строке **Цвет + Толщина**.
- Рисование мышью и touch/pointer; один законченный штрих — одна операция истории. Ластик в макете стирает нарисованный слой, **не восстанавливает пиксели исходной фотографии**. Реальная модель редактирования требует явного определения слоёв и экспорта.

### 3.4. Текст

- Под заголовком **«Надписи»** показывается **количество** и список созданных надписей.
- При отсутствии надписей отображается инструкция **«Нажми на фотографию, чтобы добавить текст.»**.
- Нажатие на фото открывает **редактируемое поле прямо в месте надписи**. После ввода и завершения надпись должна **одновременно** появиться поверх фото **и в списке**, откуда её можно снова открыть для редактирования и удалить отдельной кнопкой.
- Существующие надписи можно выбирать на фотографии и в списке; удаление должно синхронно обновлять изображение, счётчик, список и Undo/Redo. Пустую новую надпись не создавать.
- Настройки **Цвет + Размер** располагаются рядом, ниже списка; состояние текста не теряется при переключении инструментов.
- Для production отдельно требуется корректное позиционирование при разных ориентациях, кадрировании, zoom и экспорте; DOM-надпись на превью сама по себе не является сохранённой надписью в результирующем файле.

### 3.5. Фигуры

- Пять **компактных кнопок в один ряд**: **Стрелка / Круг / Квадрат / Треугольник / Звезда**.
- Следующая строка: **Цвет рамки** (палитра) **+ Толщина рамки** (ползунок).
- Ещё одна строка: **Цвет заливки** (палитра) **+ чекбокс «Залить фигуру»** (справа).
- Заполнение выключено по умолчанию. Независимые stroke/fill параметры должны попадать в сохранённое представление фигуры; для незалитой фигуры учитывать только рамку. Pointercancel не должен оставлять случайную фигуру.

### 3.6. Управление результатом

- **Назад / Вперёд (Undo / Redo)** отключены при отсутствии доступного шага.
- **«Отменить изменения»** возвращает только фотообработку к сохранённому состоянию. Если сохранённая версия уже необратима из-за отсутствия оригинала, эта кнопка не должна обещать возврат к первоначальной съёмке.
- **«До / После»** переключает предпросмотр исходного состояния текущей сессии и применённых правок, **без перезаписи**.
- История в макете ограничена 50 снимками состояния и относится к инструментам Фото; до production определить единые границы undo/redo для текста, параметров и нарисованных слоёв.

## 4. «Проверка» — Curator Review

Панель содержит **Текущий статус** (демо: «На рассмотрении»), **Решение** и **Комментарий к решению**. Четыре решения показаны в сетке 2×2: **Принять** (зелёный), **Исправить** (янтарный), **Переснять** (голубой), **Отклонить** (красный).

При выборе **Исправить / Переснять / Отклонить** комментарий обязателен. **Принять** допускается без комментария. Ниже отдельная панель **«История проверки»**; в макете одна синтетическая запись «На рассмотрении / Ожидает решения куратора».

**Граница прав:** решения доступны в production только авторизованному куратору с соответствующим доступом к этому фото/заданию. Смена статуса должна происходить через существующую доменную модель, фиксироваться в истории с автором и временем и корректно синхронизироваться. Demo изменяет только локальное состояние, не является доказательством работы review workflow.

## 5. Сохранение, отмена, навигация

1. Кнопка **«Сохранить»** неактивна без несохранённых изменений, включая данные вкладок, Public Card, текст/рисунок, решение и комментарий.
2. **«Отмена»** и возврат в Browser предупреждают о несохранённых правках. Отмена подтверждается через bottom sheet; не терять локальные изменения при случайном закрытии.
3. **Валидации макета**: заполненное название, GPS как два числа в корректных диапазонах, допустимая дата удаления, обязательный комментарий для трёх решений куратора.
4. **Смена задания** требует отдельного подтверждения, поскольку меняется папка; нельзя обойти ограничения доступа.
5. **Изменение фото при несохраняемом оригинале** требует отдельного явного подтверждения необратимости **до** окончательного commit.
6. **Если одновременно изменены задание и изображение**, обе опасные операции должны получить соответствующее информированное подтверждение; одно подтверждение перемещения не может скрытно подтверждать уничтожение оригинала. Это обязательное требование production (в демонстрации последовательность ограничена).
7. После локального сохранения в demo дата/форма и история помечаются чистыми, а статус сообщает о сохранении **только в памяти макета**. Настоящих upload, sync, photo transforms, key rotation, public links или review receipt нет.
8. Производственный Local-First: отзывчивый UI и локальный черновик, фоновая синхронизация/ошибки через единый статус. **Успех на сервере не выдумывать**; не уничтожать исходные ключи/блоки до доказанной успешной записи результата и соблюдения существующих правил.

## 6. Ограничения и технические открытые вопросы перед production

Исходник специально самодостаточен и показывает интерактивный UX, но не решает следующие задачи:

| Область | Демонстрация 3.2 | Требование к production |
| --- | --- | --- |
| Изображение | Рисованная SVG-заглушка, CSS filter/rotation/crop и Canvas/DOM overlays | Безопасный raster pipeline, согласованный preview/flattened output, корректная ориентация и качество |
| Фото и история | in-memory объект правок, до 50 history entries | Версионирование и восстановление черновика, корректное undo без доступа к удалённому оригиналу |
| Сохранение | Только локальный snapshot; статус подтверждает demo | E2EE, разрешённая версия, надёжная encrypted storage/outbox, TTL, подтверждённый commit, GC без потери |
| Правила задания | Одна условная строка-предупреждение | Реальные правила сохранения/замены original, права на редактирование и смену Assignment |
| Public Card | UI-чекбоксы | Реальный scope-aware фильтр полей и safe image, без утечки GPS/EXIF |
| Проверка | Локальный choice/comment | Роли, history/audit, события и разрешённые переходы состояний |
| GPS / тариф | Mock map и фиксированные demo-даты | Реальная картография/координаты, вычисление разрешённого срока из assignment + тариф |
| Переходы | Внешняя навигация вызывает демонстрационное сообщение | История Browser → Viewer → Editor → назад в тот же контекст |

Отдельно проверить: согласованность нескольких подтверждений сохранения, корректность redo-иконки и визуального поведения при разных масштабах, а также отсутствие потерянных надписей при закрытии редактора. Это **acceptance checks**, а не заявление, что недостатки уже исправлены в production.

## 7. Приёмка при будущем переносе

- Открыть экран из Photo Viewer, сохранить/отменить, вернуться **к тому же фото в Browser**, не потерять Shell.
- Сравнить телефон и Desktop с утверждённым Fieldwork 3.2; нижний dock и Header всегда остаются на месте, без скачков при клавиатуре или смене вкладки.
- Добавить две текстовые надписи; увидеть обе на изображении **и в списке**; переименовать, удалить одну, Undo/Redo, перейти между вкладками.
- Проверить все пять фигур, контуры, толщину, заполнение, кисть/карандаш/ластик, color sliders, пропорции и поворот на реальных фото.
- Убедиться, что экспортированная **безопасная версия** точно совпадает с предпросмотром (текст, фигуры, кадр, цвет, поворот), **не содержит скрытый оригинал или запрещённые метаданные**.
- Проверить Public Card с более строгими настройками задания, смену assignment без прав, просроченный тариф и два опасных изменения одновременно.
- Проверить решение куратора с комментарием/без него, ошибки сети, offline reload, duplicate save, interrupted sync, восстановление из местного черновика.
- Проверить реальные touch/pointer события в Safari iOS PWA / Chrome Android, keyboard focus и Escape, reduced-motion. Только явно подтверждённый владельцем внешний вид становится **ACCEPTED**.

**Итог:** это архивированный и документированный UX-эталон Photo Editor 3.2 в существующем Draft PR #56; **не merge/deploy** и не переносить напрямую в рабочий Vue runtime до отдельного решения владельца.
