# Security & Privacy — Fieldwork 1.3

**Статус: OWNER-ACCEPTED UX / NOT PRODUCTION IMPLEMENTED.** Владелец утвердил интерфейс Security & Privacy 1.3 (2026-11-09). Сохранённый автономный HTML — визуальный эталон, не production-реализация безопасности.

## Файлы и запуск

- [index.html](index.html) + [style.css](style.css) + [app.js](app.js): раздельная версия без изменения UI.
- [accepted-security-privacy-v1.3-standalone.html](accepted-security-privacy-v1.3-standalone.html): точный автономный HTML принятой версии.
- Из корня: `python3 -m http.server 8080`, затем `http://localhost:8080/docs/ux/security-privacy/`. Переключатель «Телефон / Desktop» встроен.

## Согласованный интерфейс

1. **PIN входа** — 4–8 цифр; в одном блоке с ползунком «Через какое время запрашивать PIN» от «Сразу» до «5 мин». Пока обычный PIN не установлен, ползунок неактивен, а пояснение располагается непосредственно под его заголовком. «Изменить» и «Отключить» — компактные, **выровнены влево**, не разнесены по ширине.
2. **PIN экстренного удаления** — отдельный блок; создаётся только при наличии входного PIN, ровно той же длины и с другим значением. При смене длины входного PIN прежний экстренный код сбрасывается; отключение входного кода отключает и экстренный с предупреждением. Красное описание в утверждённом HTML: «При вводе данного PIN кода, вместо обычного, доступ немедленно блокируется, данные устройства удаляются, включая всех данных из облака (при наличии связи).» Серверное удаление фактически завершается **только после подтверждения сервера**.
3. В окнах PIN используется **иконка крестика** вместо пустой кнопки закрытия. Позиция прокрутки после действий сохраняется; сообщения об изменениях показываются **сверху**, не около Dock.
4. **Другие устройства**: отключение с предупреждением «Вы уверены что хотите отключить данное устройство? Все данные с того устройства будут удалены при первом входе в приложение и наличия сети». **Без галочки**.
5. **Recovery Key**: описание «Ключ входа в аккаунт и восстановления доступа». «Показать / Скачать ключ» показывает многострочный **readonly textarea**, предупреждение «Храните его отдельно от устройства и не передавайте третьим лицам!», действия **«Сохранить на устройство» и «Скопировать» с иконкой**. Системный выбор места сохранения используется при поддержке ОС/браузера; не заменять произвольной автозагрузкой.
6. **Смена Recovery Key**: окно с предупреждением об отзыве других сессий и очистке других устройств при связи; подтверждение текущим PIN входа, если установлен; обязательная галочка об ознакомлении; кнопка «Сменить Recovery Key». Новый ключ показывается и предлагается сохранить. Реальное управление ключами нуждается в отдельном подтверждаемом криптографическом протоколе.
7. Под Recovery Key находится текст со **ссылкой на «Данные и хранилище»** для резервных копий и Recovery Vault. Не помещать backups/Recovery Vault в Security & Privacy.
8. **Dead Man’s Switch / Автоматическое удаление аккаунта при длительной неактивности**: **один общий блок** с нормальным заголовком, объяснением и **настоящим `<select>`** (off/4/6/12/24 месяца), не список из radio/checkbox. Предупреждение об необратимости и о том, что настройка не продлевает TTL файлов.

## Дизайн, границы и приёмка

- Не менять согласованный Fieldwork: Header 64px / Dock 82px, графитовый фон без синевы, зелёные акценты, умеренное закругление, закреплённые над Dock «Отмена» и «Сохранить».
- **Биометрия полностью исключена**. Поиск настроек должен поддерживать переход к конкретному полю, как в [App Appearance 1.2](../app-appearance/README.md).
- **ВАЖНО:** утверждённый UX не доказывает работу PIN, E2EE, облачного удаления, ключевой ротации или очистки другого устройства. При offline удаление из облака нельзя подтверждать до server ACK.
- Красный текст предполагает полное облачное удаление; прежний тарифный контракт допускает **сохранение зашифрованного backup на платном тарифе**. Это **нерешённый конфликт политики** перед production, не повод менять сохранённый HTML без нового решения.
- Нормативная цель для новых контрактов: [SECURITY-PIN-DEVICE-CONTRACT.md](../../product/SECURITY-PIN-DEVICE-CONTRACT.md). Старые требования о трёх независимых PIN и аварийном коде удвоенной длины отменены.

**Техническая проверка:** автономный HTML совпадает с обратной сборкой из index/CSS/JS; JavaScript проходит `node --check`; Chromium открывает исходный прототип без ошибок. Не проводились production E2E, offline/OS destructive tests, security audit. `main` и runtime не изменены.
