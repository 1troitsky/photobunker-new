# Messages — Fieldwork 1.1 (Beta)

**OWNER-ACCEPTED BETA UX / FUTURE FUNCTIONALITY / NOT PRODUCTION IMPLEMENTED.**

2026-11-09 владелец утвердил Messages Fieldwork 1.1 и попросил добавить его в Draft PR #56 именно как **утверждённый beta-шаблон для будущего модуля сообщений**. Это принятая UX-основа для дальнейшего подключения Matrix, **не** заявление о существующей работающей переписке, E2EE, доставке, голосовых сообщениях или серверном хранении.

## Файлы и просмотр

- [index.html](index.html) + [style.css](style.css) + [app.js](app.js) — интерактивная раздельная версия утверждённого HTML, только демонстрационные данные.
- [accepted-messages-fieldwork-v1.1-standalone.html](accepted-messages-fieldwork-v1.1-standalone.html) — **неизменённый автономный HTML Fieldwork 1.1**; визуальный и поведенческий эталон.
- Из корня репозитория: `python3 -m http.server 8080`, адрес `http://localhost:8080/docs/ux/messages/`; standalone открывается отдельно.
- **Телефон / Desktop** над макетом — управляющий элемент preview; **не переносить в production**.

## Дизайн и композиция (утверждено)

1. Использовать **существующий Fieldwork Shell**: Header 64 px с брендом, состоянием системы и контекстными иконками, Dock 82 px, нейтральный графит/зелёный акцент. **Список диалогов** находится внутри обычного экрана приложения; отдельный новый постоянный Header/Dock не создавать.
2. **Открытая переписка — ПОЛНОЭКРАННЫЙ МОДАЛЬНЫЙ СЛОЙ ПОВЕРХ ПРИЛОЖЕНИЯ**, а не самостоятельная страница и не две колонки постоянно открытого чата. Слой перекрывает Header, основной контент и Dock, **на телефоне и Desktop одинаково**. Если фон слоя сделать прозрачным, под ним должна оставаться неизменённая страница списка сообщений. Не восстанавливать компоновку Messages 1.0 с параллельными колонками на Desktop.
3. При открытии диалога **список не удаляется и не пересоздаётся**, его позиция прокрутки сохраняется. Закрытие возвращает на тот же список в том же месте. Открытие/закрытие — лёгкие CSS-анимации, не изменяющие геометрию Shell; `prefers-reduced-motion` отключает лишнее движение. Поддержать кнопку возврата и клавишу Escape.
4. В переписке: собственная верхняя панель с участником/командой и действиями, вертикальный список сообщений на более тёмном фоне **`#101210`**, composer снизу. Сообщения разделены увеличенными промежутками (основной `gap: 19px`, при responsive-переопределениях сохранять ощущение воздуха). Исходящие сообщения светлее входящих: утверждённый оттенок **`#315640`** для `.message.mine .bubble`, входящие **`#272927`**. Не добавлять синюю палитру или яркие декоративные панели.
5. Список показывает личные и командные диалоги с поиском и фильтрами. Внутри переписки предусмотрены отправка текста, вложения (фото, видео, файлы), голосовые сообщения, ответы, реакции, редактирование, удаление, пересылка, закреплённые сообщения, поиск по переписке, черновики и статусы доставки. Все действия сейчас реализованы **как интерактивные демо-состояния**, а не реальные Matrix API.
6. Не связывать временно будущие Messenger и старый Chatify UI/legacy Matrix bootstrap ради визуальной фиксации. Дизайн Messages 1.1 должен быть независим от транспорта и допускает заменяемый адаптер Matrix позже.
7. Приватность и Local-First — архитектурные требования будущей реализации: открытие из локального кеша/шифрованного состояния, локальный outbox без блокировки интерфейса, дедупликация, идентификаторы событий, порядок/редактирование и подтверждения доставки. **Не считать их реализованными только потому, что макет работает без сети.**

## Границы production-интеграции

- Matrix/Conduit и криптографические identity/key exchanges, E2EE, server ACL, учёт участников команды, persistent local storage, выдача вложений, обработка media metadata/TTL, retry/outbox, push notifications, sync/backfill и delivery receipts не реализованы этим прототипом.
- Выбор сообщений для удаления и «удаление для всех» в будущем должны учитывать права, офлайн-порядок, невозможность отозвать уже доставленные расшифрованные данные и удаление доступных вложений.
- Платформенный full-screen overlay должен корректно работать с мобильной виртуальной клавиатурой, safe-area, доступностью/focus trap и возвращать фокус исходному элементу после закрытия. Безопасность, пределы больших бесед, реальный iOS PWA и production E2E **не проверены** в docs-only PR.
- Сохранить интерфейс 1.1 как owner-approved **Beta**. Изменения после приёмки — новыми версиями, не переписывая сохранённый standalone.

**Проверка при фиксации:** автономный HTML разбит на соседние файлы без изменений CSS/JS; реконструкция исходника совпадает. Синтаксис JavaScript проверен `node --check` на приложенном исходнике. Владелец ранее видел интерактивный результат и прямо утвердил его. Рабочий Vue runtime и `main` не менялись.
