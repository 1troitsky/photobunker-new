# App Appearance — Fieldwork 1.3 (настройка Dock)

**Статус: OWNER-ACCEPTED UX / NOT PRODUCTION IMPLEMENTED.** Актуальный утверждённый макет — **Fieldwork 1.3 с настраиваемым Dock**. Ранее принятый 1.2 сохранён без изменений как исторический эталон. Ни один из этих HTML-прототипов не является работающим Vue-приложением.

## Файлы и запуск

- [accepted-app-appearance-v1.3-standalone.html](accepted-app-appearance-v1.3-standalone.html) — **оригинальный и неизменённый HTML версии 1.3**, утверждённый владельцем после двух последних правок.

- [accepted-app-appearance-v1.2-standalone.html](accepted-app-appearance-v1.2-standalone.html) — **историческая утверждённая версия 1.2**, не изменять.

- В панели прототипа переключение **Телефон / Desktop**. Никакого сервера, API и внешних зависимостей для демонстрации не требуется.

## Согласованные настройки

1. **Тема** — тёмная (по умолчанию), светлая, системная; выбор отражается на экране.
2. **Основной цвет** — зелёный, серый, янтарный, коралловый. Важно: выбор альтернативного акцента доступен пользователю, **но эталон оформления Fieldwork по умолчанию остаётся нейтрально-тёмным с зелёными акцентами**; нельзя самовольно вводить синие тона в общий дизайн.
3. **Размер текста** — мелкий, обычный, крупный.
4. **Стартовая страница** — Камера, Задания или Browser.
5. **Язык** — русский / английский, влияет на подписи UI в прототипе, не на содержимое пользовательских материалов.
6. **Уведомления** остаются **отдельным разделом** Settings; не переносить их в «Оформление».
7. **Кнопки «Отмена» и «Сохранить»** закреплены в нижней части **над Dock**, вне прокручиваемого содержания; при прокрутке остаются на месте. Отмена сбрасывает черновые изменения, сохранение фиксирует их в демо-состоянии.
8. Нет блока «Предпросмотр» и не нужны подсказки «Изменения показываются сразу. Чтобы сохранить их...» / «Разблокировка PIN имеет приоритет.»
9. Согласован увеличенный отступ под заголовком «Оформление / Внешний вид и поведение интерфейса» до первого блока «Тема».

## 1.3 — настройка Dock (нормативный контракт)

1. **Настройка расположена на той же странице «Оформление».** Управление составом и порядком Dock не требует нового раздела Settings. В RU/EN поиске настроек запросы «док», «панель», `dock`, `navigation` приводят непосредственно к секции Dock.
2. **От 3 до 6 пунктов**, рекомендовано 4–5. Набор доступных разделов: **Задания / Browser / Камера / Уведомления / Профиль (Настройки) / Контакты / Сообщения**. Исходный порядок: **Задания / Browser / Камера / Контакты / Профиль**.
3. **Профиль / Настройки обязателен.** Удалить его нельзя; менять его позицию можно, в том числе в начало или конец Dock. Остальные пункты добавляются/удаляются в рамках ограничения 3–6 и без дубликатов. При достижении лимита добавление блокируется с понятным объяснением.
4. **Редактор порядка:** в секции выбранных разделов — drag-and-drop и доступные без перетаскивания стрелки вверх/вниз. Доступные для добавления разделы расположены ниже. Знак **«+» в каждой строке добавления прижат к правому краю** независимо от длины названия. Для обязательного пункта нет кнопки удаления. Предусмотрен сброс состава Dock по умолчанию.
5. **Живой предпросмотр Dock:** состав, порядок и число равных зон снизу меняются в рамках черновика сразу; **«Отмена» откатывает**, **«Сохранить» принимает** все изменения оформления одновременно. Истинное сохранение между сессиями/устройствами — отдельная задача production; текущий HTML использует demo state.
6. **Повторное нажатие на активный пункт** возвращает ровно на один уровень назад внутри соответствующего раздела; переходы не должны засорять историю браузера сотнями файлов. Это поведение реализуется в production router/navigation store. В утверждённой секции настройки Dock **отдельная текстовая подсказка об этом не показывается**.
7. **Геометрия и удобство:** Dock остаётся закреплённым снизу, высотой 82px в эталонном Shell; все пункты имеют одинаковую ширину. Учесть безопасную область мобильных устройств, диапазон 320px–desktop, масштаб текста и нажатие большим пальцем. Состав меняется, но не создаёт новый Header, вторую панель или скачущую раскладку.
8. **Сообщения в Dock** — допустимая точка навигации к утверждённому **Messages 1.1 Beta**, но пока это не доказательство существования работающего Matrix-модуля.

**Приёмка 1.3:** владелец в диалоге подтвердил итоговый HTML («Отлично! теперь зафиксируем это в PR56») после утверждения двух правок: плюсики у правого края; «Профиль/Настройки» нельзя убрать, подсказка о повторном нажатии убрана. Не менять старый автономный HTML 1.2 и не переписывать остальные утверждённые UX-экраны.

## Важный контракт поиска по настройкам

- Поиск вызывается кнопкой в **Header** Settings и работает **из главного меню**, а не только на уже открытой странице «Оформление».
- Индекс должен содержать **конкретные настройки**, их названия и RU/EN-синонимы. Минимальный обязательный сценарий: пользователь открывает Settings → поиск → вводит **«язык»** или **`language`** → выбирает результат **«Язык»** → открывается «Оформление», область контента прокручивается **непосредственно к полю выбора языка**, фокус переходит к соответствующей секции.
- Аналогично поиск по theme/тема, color/цвет, text size/размер текста, launch page/стартовая страница должен открывать конкретное поле.
- Для ещё не реализованных разделов допустима отметка недоступности, но **нельзя выдавать переход на корневую страницу раздела за переход к найденной настройке**. При production реализации индекс должен охватывать все введённые настройки и оставаться независимым от локализации.
- История «Назад» должна возвращать в предыдущий маршрут/поиск без неожиданного перехода к корню приложения.

## Общий Shell и ограничения

- Сохранять установленный Fieldwork: Header **64 px**, Dock **82 px**, бренд PhotoBunker, системный статус, нейтральная тёмно-серая тема по умолчанию, умеренное закругление action buttons, одна зелёная кнопка тарифа (в демо **«Тариф: Unlimited (267 дней)»**).
- При переносе не дублировать Shell/статус/док и не копировать demo state как production preferences. Учитывать `prefers-color-scheme`, локальные настройки и ограничения устройства. Production persistence, перенос настроек между устройствами, полноценная i18n, обработка system theme и доступность требуют отдельной реализации.
- Ни API, ни Local-First, ни PIN/crypto/storage, ни существующие приложения/экраны не изменены; `main` не затронут.
- Техническая проверка фиксации: точная обратная сборка HTML из разделённых CSS/JS; `node --check` JavaScript успешно выполнен. Владелец **отдельно подтвердил** UX 1.2; это не proof production integration/E2E.
