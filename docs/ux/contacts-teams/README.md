## 1. Компоновка общей страницы

- Единый **Header 64px**: [pb], название и системный статус под ним. **Единственная контекстная иконка справа — Blacklist** (заблокированные контакты). Открытие Blacklist не порождает ещё одну независимую шапку.
- Заголовок **«Контакты и Команды»**, затем одно горизонтальное меню: **Команды (N) / Контакты (N)**, где числа вычисляются из текущих данных. Никакого второго подменю «Контакты / Заблокированные» и лишнего повторного заголовка «Контакты» ниже.
- Общий скроллинг контента и неизменный **dock 82px**: Задания / Browser / Камера / Контакты (активен) / Профиль.
- В верхнем переключателе интерактивного макета **Телефон / Desktop** можно сравнить адаптивную геометрию. Это тестовый переключатель ширины, **не дополнительная функция продукта**.

## 2. Команды — список

- **Сразу под вкладками** размещена самостоятельная полноширинная кнопка **«Создать команду»**.
- Далее список команд: **название, краткое описание, мини-аватары участников, число участников** и меню `•••`. Не использовать большую бессодержательную иконку «человечки» слева от названия.
- Нажатие на команду открывает её карточку внутри общей навигации; кнопка `•••` в списке — действия команды (в том числе открытие, редактирование/удаление при наличии прав или выход).
- Новая команда: **название**, **описание** (необязательно), **участники**, сохранение только явной кнопкой **«Создать команду»**. При редактировании — «Сохранить изменения». Не создавать и не сохранять команду при закрытии формы или отмене.

## 3. Карточка команды

- Верхняя строка возврата; справа вместо многоточия — **шестерёнка**, которая **сразу открывает настройки команды**, если это разрешено ролью.
- В блоке команды: **название**, **количество участников/статус владельца** и **описание непосредственно под ними**. Нет декоративной большой иконки команды.
- Раздел **«Участники»**: компактные строки с маленьким круглым аватаром, идентификатором/именем и ролью. Справа у **каждого участника, включая владельца, меню `•••`**. Действия, недопустимые владельцу или роли, должны быть недоступны, даже если меню открывается.
- Под участниками — одна **полноширинная кнопка «Добавить участника»** (при наличии прав), без отдельной лишней кнопки «Настройки участников».
- При нажатии `•••` участника открывается нижняя панель ролей и доступа, **без нижней кнопки «Назад»**. Закрытие — стандартная кнопка крестика в шапке панели.
- **«Задания команды»**: связанные задания с названием и статусом. Удаление команды не должно молча удалять связанные задания.

## 4. Участники и приглашения

- **Контакт → участник команды**: пользователь должен сначала находиться в контактах, затем его можно выбрать в команде. Это подтверждённое правило из `docs/16-OPEN-PROBLEMS-AND-QUICK-TASKS.md` (**AS-05**).
- Выбор из контактов — строки с аватаром, `@username` либо `#ID` и поиском. Роли: **Владелец / Куратор / Исполнитель / Наблюдатель**. Уровень доступа: **По правилам задания / Без доступа / Только предпросмотр / Полный доступ**.
- Меню владельца показывается, но роль владельца и его собственный статус нельзя произвольно менять. Для других участников редактирование/удаление зависит от настоящих прав. Подтверждения и сохранение выполняются только явным действием.
- В demo роли и доступ представлены локальными значениями `role`/`scope`; в production политики и E2EE-доступ проверяются сервером и криптослоем. **Нельзя применять изменение только к списку без фактического обновления доступа.**
- Не добавлять в интерфейс лишние обязательные «проверить/подтвердить участника» шаги: подтверждение прав и ключей — внутреннее поведение.

## 5. Контакты и Blacklist

- Вкладка **«Контакты (N)»**: одно поисковое поле **по `@username` или `#ID`**, далее компактные **прямоугольные строки** контактов с аватаром и публичным идентификатором. Нажатие открывает карточку пользователя.
- Поиск может найти доступный профиль вне текущих контактов, после чего доступна явная кнопка **«Добавить в контакты»**. Поиск не гарантирует выдачу скрытого профиля; в production правила видимости обязательны.
- **Карточка контакта**: профиль, переход в сообщения и контекстные действия добавления/удаления/блокировки с подтверждением, где необходимо.
- **Blacklist** открывается **только отдельной кнопкой в Header**. Там можно просмотреть заблокированных пользователей и разблокировать. Заблокированные не появляются в обычном списке контактов или выборе членов команды.
- Удаление контакта не эквивалентно удалению/деактивации членства в команде — для этого нужны явные доменные правила.

## 6. Состояние, безопасность, ограничения макета

Демо использует **синтетические контакты, команды, роли, задания** и локальное состояние текущей вкладки. Оно демонстрирует создание, редактирование, удаление и навигацию, **не** реализует настоящий account lookup, server commit, Identity, ACL/E2EE, приглашения или offline sync. Status/toast — визуальные примеры, не подтверждение серверного сохранения. Рабочая реализация обязана быть Local-First, без блокирующих сетевых загрузок, но fail-closed для прав и защищённого содержимого.

Технические правила проекта: **AS-04** создание команды должно немедленно вернуть ID и корректно привязать его к заданию; **AS-06** поиск по точному ID/slug и privacy-aware карточка контакта; **AS-07** полноценные аватары, роли и карточки команды вместо технических идентификаторов; **AS-08** отдельный статус каждой операции обновления членства; **UI-11** закрытие формы никогда не инициирует создание.

## 7. Приёмка и дальнейшая работа

**На данном шаге утверждён и задокументирован только экран Contacts & Teams Fieldwork 1.1.** Сохранены оригинальный автономный HTML и раздельные исходники, обратная сборка должна давать **точное совпадение**. Синтаксис JS проверяется отдельно. Ранее владелец принял интерактивный вариант; новый production/UI E2E после фиксации в PR **не считается пройденным**.

**Не изменять:** `main`, рабочие Vue/TS, Assignment Editor 2.2, Browser v3, File Viewer 1.0, Photo Editor 3.2, Video & Audio Editor 1.1, Camera 1.2. При новой UX-итерации сначала показать отдельную HTML-страницу и получить явное согласование, только затем менять PR.
