# Camera — Fieldwork 1.2 · OWNER-SELECTED UX

**Состояние:** согласованный UX-макет и его исходный код. **НЕ production implementation.** Уточнение владельца: 2026-11-07. Дизайн продолжает общий Fieldwork (Spotify-inspired dark) из PR #56 и основывается на актуальном CameraView.vue.

## Источники и просмотр

- [index.html](index.html) — автономная разметка: Header, Фото / Видео / Аудио, область предпросмотра, кнопки, dock, шторки, слепой режим.
- [style.css](style.css) — извлечённые стили принятого HTML 1.2; не являются независимой системой Shell для Vue.
- [app.js](app.js) — интерактивная демонстрация: настройки, задания, синтетический кадр, условная съёмка с устройства, MediaRecorder, GPS, статус и пресеты.
- [Общий UI Shell Contract](../UI-SHELL-CONTRACT.md) — обязательный для переноса в приложение.
- Действующий производственный экран для анализа перед переносом: \`compat/assignment-release/apps/web/src/views/CameraView.vue\`. Требования: \`ts_and_ux.md\`, блок Camera. **Не заменять существующий capture, crypto/storage и локальный outbox демо-алгоритмом.**

Открыть локально из корня репозитория:

~~~sh
python3 -m http.server 8080
~~~

Адрес: **http://localhost:8080/docs/ux/camera/**. Без npm, внешних сервисов и реального аккаунта. Выбор «Телефон / Desktop» — переключение ширины макета. Состояние, пресеты и отснятые материалы в демонстрации существуют **только в памяти вкладки**.

## 1. Структура и минималистичная камера

Сохранить без перестройки каркаса:

1. **Header 64px**: слева [pb] PhotoBunker, под названием системный статус/индикатор; справа строго три контекстные иконки **Перевернуть (две круговые стрелки 🔁) / Фонарик / Слепой режим**. Убрать прочие действия и GPS из Header.
2. **Горизонтальный переключатель** непосредственно под Header — **Фото / Видео / Аудио**, с зелёной линией под активным режимом.
3. **Центральная область**: для фото и видео — масштабируемый видоискатель (пресет пропорций, 3×3 сетка по настройке); для аудио — отдельный интерфейс диктофона, **без изображения/видеопотока**. Не рисовать надписи «4:3 · Высокое», «Демонстрационный предпросмотр», «Снимки не записываются на сервер в демо» поверх камеры.
4. **Нижняя зона управления**: GPS **по центру над затвором**, если разрешён показ статуса, далее три действия **Задание / Снять / Настройки**. В видео и аудио центральная кнопка запускает или останавливает запись, отображается таймер.
5. **Общий dock 82px**: Задания / Browser / Камера (активна) / Контакты / Профиль. Те же размеры, цвет и расположение, что на других экранах. Статус Header — единый системный статус, не отдельный журнал каждой страницы.

Не размещать второй, дублирующий набор кнопок поверх preview. Вкладки не должны сдвигать Header/dock и ломать touch safe areas. Bottom sheets открываются поверх Shell; доступно закрытие и клавиатурная навигация.

## 2. Режимы съёмки

| Режим | UX | Контракт для production |
| --- | --- | --- |
| **Фото** | Один tap по белой круглой кнопке создаёт снимок; необязательная сетка 3×3; кадр/категория/описание и выбор задания используются для будущего материала | Полноценная camera capture API, предусмотренное правилами задания изображение, безопасная локальная запись/обработка, metadata и E2EE/outbox |
| **Видео** | Красная кнопка start/stop, индикатор записи и таймер; отдельное качество 480p / 720p / 1080p; звук можно включить по настройке | MediaRecorder/совместимый fallback, реальный mime/codec, разрешения, безопасная локальная запись чанков и обработка прерываний |
| **Аудио** | Диктофон без видеопотока, красная кнопка и таймер; выбор качества 64 / 128 / 192 / 256 кбит/с | Получать только микрофон, проверять реальный формат, не обещать точный битрейт если браузер его не соблюдает; добавить audio в photo-centric доменные модели **только отдельным решением/реализацией** |

**Ограничения длительности** (настройка пресета): видео **5–300 секунд** (5 сек — 5 мин), аудио **5–3000 секунд** (5 сек — 50 мин). UI автоматически останавливает запись на заданном лимите. Производственная запись должна корректно завершить и сохранить уже снятый материал при достижении лимита, прерывании/смене доступа, закрытии страницы и сбое кодека. Не полагаться на видимый счётчик как на единственное ограничение.

Общая кнопка для фото, видео и аудио — единая точка действия; нельзя запустить две записи одновременно. Режимы не переключаются во время записи. В демонстрации снятые файлы доступны через «Последняя съёмка» в статусе: фото preview, видео player, аудио player; внешней загрузки и синхронизации нет.

## 3. Слепой режим

- Верхняя кнопка зачёркнутого глаза включает непрозрачный, простой экран с иконкой и заголовком **«Слепой режим»**.
- Текст сохраняется дословно из согласованного макета: **«Что-бы другие не видели, что вы делаете 👻»**.
- Присутствуют центральная **кнопка съёмки/записи**, при записи — таймер и элемент **«Вернуться назад»**.
- **Важнейшее правило:** режим только **скрывает предпросмотр**, **НЕ останавливает** уже работающую камеру и начатую запись. Видеопоток не перезапрашивается при возвращении. В режиме «Аудио» не включать камеру.
- Можно слушать события клавиш громкости, если браузер их действительно присылает. На мобильных браузерах, особенно iOS, нажатия **часто не доступны веб-странице**. Поэтому экранная кнопка съёмки доступна **всегда**, а не только при неуспехе аппаратной кнопки. Demo дополнительно обрабатывает Space при скрытом экране.
- Слепой режим **не равен системной блокировке**: не гарантирует скрытие системных индикаторов записи камеры/микрофона, активного приложения, уведомлений и отображения иконок разрешений. Не обещать «невидимую» или бесшумную запись. Системные разрешения и требования законов сохраняются.

## 4. Панель «Задание и данные съёмки»

Одна **объединённая** bottom sheet вместо отдельных панелей задания, категории и описания:

1. Выбрать назначенное задание (в макете: «Фасады — Site A», «Интерьер — зал 02» или личная съёмка). После выбора видны **инструкции задания**.
2. Если правила требуют GPS — показать **«GPS обязателен по правилам задания»**.
3. Если правила требуют категорию — показать **«Категория обязательна по правилам задания»**. Прототип использует условный \`categoryRequired\`: «Фасады — Site A» — **true**, прочие два демо-задания — **false**. При обязательной категории поле не может остаться пустым; защита предусмотрена и при завершении формы, и перед началом новой съёмки.
4. Ниже **Категория / Ракурс (если список ракурсов задан) / Описание съёмки**. Информация применяется к следующим материалам. Существующие материалы не переписываются задним числом.
5. Кнопка **«Готово»**. При смене задания отражаются доступные категории/ракурсы, а принудительная GPS-настройка применима независимо от выбранного пресета.

**Production:** обязательность категории, GPS, описания, доступ к заданию, права съёмки, список допустимых категорий и ракурсов задаёт **серверная/локально-кэшированная политика задания**, а не поле в макете. В offline режиме локально применять последнее подтверждённое правило; не обходить ограничение, скрыв уведомление. Удобная UI-валидация — не замена доменной.

## 5. Панель «Настройки»

Верхний раздел **«Пресеты камеры»** содержит выбор существующего пресета, редактируемое название и **две кнопки внутри раздела**: **«Сохранить пресет» / «Добавить пресет»**. Не помещать в низ панели дублирующее «Сохранить как новый». Пресет включает настройки фото, видео, аудио и камеры; его параметры можно обновлять и создавать новый набор. Демо-пресеты не сохраняются после перезагрузки, production требует durable Local-First хранение/синхронизацию согласно разрешениям.

**Фото:** пропорции 1:1 / 4:3 / 3:2 / 16:9; качество Максимальное / Высокое / Среднее / Низкое; масштаб; фонарик; переключатель **«Сетка кадрирования 3х3»**, подпись **«Не показывается на готовых кадрах»**.

**Видео:** качество 480p / 720p / 1080p; максимальная длительность **5 сек — 5 мин**; записывать звук в видео по разрешению микрофона.

**Аудио:** качество **64 / 128 / 192 / 256 кбит/с**; максимальная длительность **5 сек — 50 мин**. Звук в аудиорежиме не требует доступа к видеокамере.

**Геолокация:** два отдельных переключателя — **«Отслеживать GPS»** (влияет на попытку получения координат) и **«Показывать GPS над кнопкой «Снять»»** (только видимость статуса). Когда GPS обязателен по правилам задания, отслеживание нельзя выключить из настроек; отсутствие доступной/точной позиции обрабатывается согласно действующей политике задания, а не подменяется вымышленным значением. Текущий статус/кнопка «Определить координаты» есть внутри раздела. Один GPS watcher на приложение, без обещаний фонового GPS на iOS PWA.

**Разрешения устройства:** отдельные кнопки **«Разрешить камеру»** и **«Разрешить микрофон»**. Пояснение: **«Камера нужна для фото и видео; микрофон — для аудио и видео со звуком. Браузер запросит разрешение отдельно.»** Убрана видимая фраза «Нужен HTTPS или localhost.». **Техническое требование браузера о secure context остаётся действующим**; если разрешение невозможно, выводить понятную ошибку по фактической причине, а не постоянную техническую подсказку в настройках.

## 6. Ограничения макета и перенос в production

HTML-прототип — самостоятельная демостраница. **Фото/видео/аудио в памяти браузера не считаются сохранёнными материалами PhotoBunker**. Реальная \`getUserMedia\` и \`MediaRecorder\` зависят от устройства, разрешений, кодеков и HTTPS; демонстрационный видеоисточник может использовать Canvas. Пресеты и назначенные задания — синтетические, без реальных учётных записей.

Для следующей производственной задачи:

- Переиспользовать действующий \`CameraView.vue\`, \`../local/camera\`, camera context, существующие permissions, encrypted photo storage и Local-First/outbox; **не копировать** SVG/Canvas demo как production pipeline.
- Отдельно определить доменную сущность **Media/Recording** либо корректное расширение существующей модели для **видео и аудио**: E2EE, длительность, mime/codec, обложки/превью, возврат в Browser, editor, sharable scopes, TTL, GC, лимиты хранилища/тарифа. Сегодняшний PR **не внедряет** новые типы файлов в API и не ослабляет безопасность фотографий.
- Не сохранять raw photo/video/audio в галерею ОС; в production — только локально допустимый защищённый буфер и зашифрованный upload. Отдельно учитывать скорость записи, размер длинного аудио, размер видео и потерю потока при сворачивании PWA.
- Для видео/аудио проверить реальные разрешения, качество и поведение MediaRecorder; fallback и перезапуск должны быть честными. **Внешняя отправка не стартует автоматически** после просмотра демо.
- Управление flashlight, zoom и переключением камер — только по фактическим capability устройства; не показывать ложный success, если аппаратная функция недоступна. Клавиши громкости — best effort, экранный затвор в слепом режиме обязателен.
- Следовать общему \`docs/ux/UI-SHELL-CONTRACT.md\`: один Header, один dock и центральный журнал операций. GPS/сохранение/ошибки — в общем status controller; не блокировать открытие камеры сетевым ожиданием.

## 7. Приёмка будущей реализации

Минимальные сценарии: мобильный portrait и desktop; Фото / Видео / Аудио; переключение камер и фонарик; три настройки и длительности; новый/перезаписанный пресет; роль/правила задания; обязательная/необязательная категория; обязательный/необязательный GPS (отслеживание отдельно от показа); корректный возврат из слепого режима при живом потоке; кнопка съёмки в слепом режиме при недоступных volume keys; автоматическое завершение записи; обработка запрета permissions;  offline/reload/очередь. Проверить реальные **Safari iOS PWA / Chrome Android** отдельно; не считать desktop demo доказательством работы hardware-возможностей.
