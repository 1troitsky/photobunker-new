## Открытие прототипа

- [`index.html`](index.html) — самостоятельный HTML экран.
- [`style.css`](style.css) — локальный CSS: оболочка, токены, адаптивность, элементы.
- [`app.js`](app.js) — демонстрационные данные и обработчики вкладок, поиска, меню, статуса, сортировки и форм.
- Открывать `index.html` из браузера или запустить в корне репозитория `python3 -m http.server 8080` и открыть `http://localhost:8080/docs/ux/assignments/`.
- Не требует npm, внешних шрифтов, внешних изображений, API или доступа к приватным данным.

## Согласованные решения

1. **Концепция:** Fieldwork, Spotify-inspired dark: почти чёрный фон, графитовые секции, дозированный зелёный акцент только для статуса, прогресса, активной навигации и главного действия. Плотная, но читаемая компоновка; небольшие скругления кнопок.
2. **Единый UI Shell:** `[pb] PhotoBunker` со статусом **под названием**, справа только иконки поиска, настроек и нового задания **без обводок**. Постоянная прокручиваемая рабочая зона, увеличенный нижний dock на 5 пунктов. Header и dock не должны перезагружаться при переключении экрана. Status: нормальное состояние без навязчивых уведомлений; полезные загрузки/подключения/ошибки доступны при нажатии.
3. **Заголовок «Задания»:** справа **маленькие** счётчики `Всего / Активных / Готово`, объединённые одной **слегка приподнятой тёмной подложкой**. Это обновление Fieldwork 4.2.
4. **Вкладки:** `Активные / Архив / Все`. Поиск по названию и инструкциям; сортировка из настроек (в product spec: по созданию, редактированию и добавлению фото).
5. **Задания не имеют обложек.** Допустима маленькая выбранная иконка 43×43 px, как мини-аватар. В макете иконки примерные; сохранение выбора иконки в production требует отдельного продуктового решения и безопасного обновления модели. Никаких вымышленных превью заданий.
6. **Сразу под названием:** статус; иконка участников и количество; необязательное название команды. Всё в одной гибкой строке, переносится при узкой ширине.
7. **Содержимое карточки:** описание/инструкции (до 2 строк в списке); начало, окончание и длительность крупным шрифтом; прогресс **`12 / 30` слева и `40%` справа**, без слова «прогресс». Когда цель по количеству снимков не задана — просто количество подтверждённых фото без фальшивой шкалы.
8. **Кнопка «Снимать»** доступна и для запланированных задач, если пользователь имеет права (это новое требование владельца; текущий production-код блокирует съёмку до startsAt — при переносе менять условие в доменной логике согласованно). Для завершённых заданий скрыта.
9. **Browser** показывается только при наличии фото **и** права просмотра. Переход должен открывать scope конкретного задания, не смешивая фото из других задач.
10. **Меню задания:** открыть, редактировать (если разрешено), дублировать, завершить/возобновить (если разрешено), удалить (если разрешено). В production использовать существующие подтверждения и права доступа.
11. **Адаптивность:** телефон — одна колонка; Desktop — две колонки. Заголовок, общий контейнер и dock остаются согласованными.

## Что является настоящим функционалом, а что демонстрацией

| Демонстрация | Источник для реализации в production |
| --- | --- |
| Данные 4 вымышленных заданий | `localTasks`, `assignments`, `receipts`, `photos` в `src/views/AssignmentsView.vue` |
| Счётчики | производные от отфильтрованного по доступу набора задач (для верхнего общего итога — от всех доступных задач) |
| Фото и % | текущая функция `count(id)`, считает только подтверждённые снимки/receipts; деление на `targetCount` только если цель задана |
| Роли / доступность кнопок | существующие `canCapture`, `canBrowse`, `canManage`, время и права из текущего домена |
| Участники и команда | фактические `Task.participants`, `teamName`, с защитой приватности; не захардкодить демонстрационные числа в production |
| Прогресс, даты, duration | `startsAt`, `finishesAt`, `targetCount` и локаль; длительность — календарная разница start/end, без придуманного срока |
| Переход в Browser | `/browser?assignment=<id>`; не открывать при отсутствии фото/права |
| Переход в Camera | существующий `startTask(task)` / `/camera`; поддержка scheduled требует отдельной функциональной проверки |
| Создание/редактирование | действующий `AssignmentEditView.vue` со всеми настоящими полями, не урезанная demo-форма |
| Статус приложения | существующий `AppStatusIndicator` + реальные состояния загрузки, sync и соединения; demo-переключатель — не реальная диагностика |

Demo CRUD изменяет только массив в памяти страницы. Кнопки Camera/Browser/других пунктов dock демонстрируют точки перехода в диалогах; **не выдают себя за работающие экраны или серверные операции**.

## Контракт будущего UI Shell

`AppShell` владеет высотами viewport/header/dock и safe-area. `PageLayout` — едиными отступами, шириной, заголовками и прокруткой. Никакая страница не переопределяет геометрию shell через разрозненные CSS. Камера и просмотрщик имеют явный immersive mode, а не собственную вторую систему размеров.

Это **цель при переносе**, не команда переделать весь UI сейчас. Перенос в `compat/assignment-release/apps/web` делать отдельным PR/задачей и принимать на настоящем телефоне. По `AGENTS.md` код считается `IMPLEMENTED` до подтверждённого просмотра и `ACCEPTED` — только после прямого согласия владельца.

Источники требований: [`ts_and_ux.md`](../../../ts_and_ux.md) (общая схема, задания, статус, dock, Local-First), текущий [`AssignmentsView.vue`](../../../compat/assignment-release/apps/web/src/views/AssignmentsView.vue).
