## 1. Общая композиция

Прежний тёмный Fieldwork, зелёный акцент, Header **64px** (кнопка назад, [pb] и статус под названием), одна прокручиваемая рабочая зона, неизменная нижняя панель создания задания. Есть переключатель **Телефон / Desktop**. Четыре вкладки в том же порядке:

**Основное / Файлы / Участники / Правила.**

Название **«Файлы»** в табах не означает замену внутреннего заголовка **«Камера»** — он сохраняется внутри вкладки. Демо даёт локальное создание, выбор пресета, команды и участников без сетевых операций.

## 2. Основное: сроки и удаление

- **Название**, **инструкции**, **начало** (текущая локальная дата/время по умолчанию; нельзя задать раньше текущего момента), необязательное **окончание** (минимально — завтрашний день и позже начала).
- Отдельно: **«Запретить добавление файлов до начала»** и **«Запретить добавление файлов после окончания»**; оба выключены по умолчанию. Ограничение предназначено и для съёмки, и для загрузки.
- **«Автоматически удалять файлы»** — выключено по умолчанию; если включить, выбрать дату **«Удалить файлы после»**. Пока выключено, действует политика хранения по тарифу и его продлению, а не обещание вечного хранения.
- **«Автоматически удалять задание»** — выключено по умолчанию; при включении дата **«Удалить задание после»** и независимый переключатель **«Удалить также файлы задания»**. Личные копии других участников не становятся автоматически доступными для удаления владельцем задания.
- **Ключевой уточнённый сценарий:** если явная дата окончания **не установлена**, дата автоматического удаления файлов **или** задания определяет эффективный срок завершения задания. При одновременном включении обеих дат в прототипе используется **более ранняя** из них. Если окончание установлено явно, автоматическое удаление не может предшествовать ему. UI выводит рассчитанную дату и источник срока.
- Значения дат и автоматическое удаление — **поля макета**, не фоновый планировщик. В production совместить с действующими TTL, правами, тарифом и подтверждением удаления.

## 3. Файлы: пресет камеры и разрешённые медиа

Раздел **«Камера»**: выбор пресета и кнопка **«Открыть настройки камеры»**.

Раздел **«Разрешённые типы файлов»**: три независимых переключателя **Фото / Видео / Аудио** (в макете разрешены все три). Для каждого включённого типа:

- Полноширинное поле **«Нужно фотографий» / «Нужно видео» / «Нужно аудио»** находится **на следующей строке** после заголовка и подписи **«Только для прогресса»**.
- Количество **необязательно**: фото **1–9999**, видео и аудио **1–999**. Используется **только для прогресса**, не запрещает создание дополнительных файлов.
- Свои **инструкции / список ожидаемых материалов** для фото, видео и аудио. В прототипе количество и инструкции сохраняются при временном выключении типа, но к заданиям применяются лишь разрешённые типы.
- Необходимо разрешить **хотя бы один** тип. Параметры пресета не должны переопределять ограничения типа, установленные заданием.

## 4. Участники

- **Выбрать команду** из существующих. В списке выбора **нет пункта «Настройки команды»**.
- Ниже карточки команды — отдельная текстовая ссылка **«Перейти к настройкам команд»**. Демонстрационный переход не является реальным переходом на страницу Teams.
- Основной список **«Участники»**: слева маленький круглый аватар, справа **`@username` либо `#ID`**, без избыточных подпунктов в основной строке. Контекстное меню участника управляет ролью и доступом к файлам.
- По **«+ Добавить участника»** — панель **Контакты / Поиск**, поиск по UserID или @UserSlug. **Принятый последний фикс 2.2:** результаты контактов должны быть в **отдельных прямоугольниках**, каждый визуально как строка основного списка: небольшой круглый аватар слева, `@username` или `#ID` рядом. Не возвращать упрощённый неоформленный список.
- Данные участников/команд внутри HTML синтетические; права в будущем определяет домен и сервер.

## 5. Правила

Принятые переключатели/зависимые поля (не сокращать при переносе):

- **Нумерация:** AssignmentID как часть имени файла, например NAME0001 (включено по умолчанию).
- **Импорт:** разрешить добавление файлов из других приложений, устройств и по ссылке (включено).
- **Public Card:** разрешена по умолчанию; дочерние поля: автор/команда (выкл.), дата добавления (выкл.), дата изменения (выкл.), GPS (вкл.), описание (вкл.), теги (выкл.), метаданные (выкл.). **Public Card — набор допустимых полей, не автоматическая публичная ссылка и не обход ACL.**
- **Категория и теги:** независимые требования обязательности; при ограничении списка раскрывается редактирование разрешённых значений. По умолчанию требования выключены.
- **Описание:** необязательное по умолчанию; при требовании минимальная длина (в макете 10 символов).
- **GPS:** отдельная опция обязательности, с учётом требований задания и разрешений устройства.
- **Редактирование файлов**, зависимое **сохранение оригинала**, **удаление оригинального файла** (не управляет личными копиями вне задания).
- **Просмотр:** разрешён по умолчанию; зависимый режим **только предпросмотр**, без доступа к полным файлам.
- **Передача:** разрешена по умолчанию; независимо ограничить получателей участниками и/или право инициировать передачу только кураторами.

При внедрении требуется фактическая модель прав и scope для фото, видео и аудио, включая безопасные версии, Original/Edited, E2EE, TTL и локальный outbox. Видимый переключатель не является серверным разрешением.

## 6. Проверка и границы

Сохранён **точный утверждённый исходный HTML 2.2**, разделён на HTML, CSS и JS с гарантией обратной сборки. Проверен **синтаксис JavaScript**; новая отдельная браузерная E2E-проверка версии из GitHub не заявляется. Это **дизайн**, не изменение `AssignmentEditView.vue` и не внедрение в production.

Основные сценарии будущей реализации: локальные/различные часовые пояса, начало и удаление до/после окончания, две даты автоудаления, запрет импорта по срокам, смена типов, планы без целей, участники/список контактов, Public Card и права, mobile/desktop, сохранение черновика offline, срок тарифного плана. Все операции удаления/переноса требуют явных доменных разрешений.

**Порядок изменений:** сначала отдельный интерактивный HTML → явное утверждение владельца → изменение PR. Не менять утверждённые другие экраны под видом работы над Assignment Editor.
