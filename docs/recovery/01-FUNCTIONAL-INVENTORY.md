## Как читать статусы

| Статус | Значение |
| --- | --- |
| **C** | Кодовая реализация явно прослеживается в исходниках; **не** значит, что она собирается или работает. |
| **P** | Часть функции прослеживается, но полноценный сценарий/правило/права отсутствуют или не соединены. |
| **M** | Нативного PB2 сценария/контракта в изученном дереве нет. |
| **H** | Сценарий явно заблокирован флагом безопасности/отключён сервером. |
| **N** | Доказательств соответствующей функции в исследованных источниках не найдено. |
| **X** | Функция сознательно исключена из первоначального PB2 согласно действующим нормативным документам. |
| **D** в приоритете | Не кодить до решения владельца по конфликту спецификаций. |

Приоритет `P0` — обязательный безопасный пользовательский сценарий/release blocker; `P1` — восстановление основного продукта, `P2` — UX/delivery позже. PB1 `C` означает наличие реализации в старом коде, **не подтверждённое тестами**; источник PB1 нельзя слепо копировать в PB2.

## Вывод и граница безопасности

- PB1 содержит модели заданий/пресетов/настроек и значительный UI, но связан с предыдущей Identity, Matrix/Workspace и прежним хранением. Использовать для адаптации алгоритмов и UX, не переносить весь runtime.
- PB2 имеет единые модульные boundaries, но ещё не восстановил требуемые сквозные потоки. `compat/assignment-release/` в #42 — сохранённый источник, **не** рабочие функции PB2.
- Серверная настройка `recipient_thumbnail_reads_enabled=false` остаётся строгим P0 STOP. Не включать ради зелёного CI.
- Конфликты из owner visual-ux (часовые сроки, Never, тарифы 60d/Unlimited, 80px) и PB2 approved storage/identity — см. [решения](04-OWNER-DECISIONS.md); здесь они не разрешены молча.
- Каждый пункт переводится в Verified только с кодовым diff, зелёными CI и измеримым E2E/owner acceptance. См. [план](02-RESTORATION-PLAN.md).
