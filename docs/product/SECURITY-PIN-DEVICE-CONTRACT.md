# PhotoBunker — PIN, Security, Devices & Recovery: целевой контракт

**OWNER-AGREED PRODUCT / IMPLEMENTATION PENDING.** Решение 2026-11-08/09; не доказательство реальной безопасности. Канонический UX: [Security & Privacy 1.3](../ux/security-privacy/README.md).

## 1. Два PIN и их зависимости

- `app_pin`: необязательные **4–8 цифр**; настройка повторного запроса при возврате от **«Сразу» до «5 мин»**. Не является Recovery Key и не заменяет E2EE.
- `emergency_pin`: необязательный, **только при существующем app_pin**, точно **та же длина 4–8 цифр**, **не совпадает** с app_pin. Вводится в то же поле разблокировки, но имеет отдельный разрушительный сценарий, **не является запасным входом**.
- Создание/смена обоих кодов — с подтверждением. Изменение длины app_pin **инвалидирует emergency_pin**; отключение app_pin автоматически отключает emergency_pin с предупреждением. Смена обычного PIN не должна допустить его совпадения с аварийным.
- **Схема 2026-11-06 «4–6 цифр + Emergency 2×N в двух частях» отменена.** Отдельный Local-delete PIN и FaceID/TouchID **не входят** в согласованный UX 1.3.
- Не хранить открытые PIN/верификаторы в логах или localStorage. Требуются проверенная KDF, соль, rate limiting, crash/reload/error tests, отдельный threat review.

## 2. Экстренное удаление и честные состояния

При вводе аварийного PIN немедленно блокировать локальный доступ, разрушать локальные ключи/grants идемпотентно и инициировать подписанный серверный revoke/delete intent, если доступна сеть. Offline → операция сервера **pending**; «cloud deleted» только после **server ACK**. В PWA нельзя гарантировать forensic wipe, очистку уже скачанных копий или удаление с выключенных устройств.

Красный текст интерфейса принят владельцем, но требует точного согласования с [BILLING-TARIFF-CONTRACT.md](BILLING-TARIFF-CONTRACT.md): **OPEN/P0** — обещание удалить **все облачные данные** конфликтует с ранее согласованной возможностью сохранить существующий зашифрованный backup платного тарифа для восстановления. До отдельного решения **не реализовывать необратимое удаление платного backup**, не заявлять одновременно несовместимые исходы. Требуется режим/политика хранения копий, предварительное предупреждение и negative/security tests.

## 3. Управление устройствами

При «Отключить» вывести предупреждение без дополнительной галочки. После подтверждения отозвать серверные сессии и будущий доступ; локальная очистка другого устройства возможна только при его последующем запуске и наличии связи. Не обещать мгновенного удалённого физического уничтожения offline материалов. Состояния `revoked`, `wipe_pending`, `wipe_ack` различать, операции идемпотентны.

## 4. Account Recovery Key

- Ключ — секрет восстановления по [11-IDENTITY-AND-KEYS.md](../11-IDENTITY-AND-KEYS.md), а не пользовательский PIN. Показывать только после локальной авторизации в **readonly textarea**, не раскрывая в логах/URL.
- Дать **«Сохранить на устройство»** через системный выбор места / share sheet там, где платформа поддерживает, и **«Скопировать»** с иконкой и явным результатом. Если платформа не позволяет выбрать место, показать ограничение, не выполнять молча автосохранение в неизвестный каталог.
- Смена ключа: предупреждение об отзыве прочих сессий, PIN-проверка при установленном app_pin, явная галочка, затем атомарная ротация key/envelope с проверяемым новым Recovery Key и возможностью его сохранить. Другие устройства при следующем подключении теряют доступ и по возможности очищаются; нет гарантии моментального offline wipe.
- Backups, Recovery Vault, восстановление данных — **«Данные и хранилище»**, здесь ссылка-переход.

## 5. Dead Man’s Switch

В одном блоке опция удаления **аккаунта** при неактивности: `<select>` **Выключено / 4 / 6 / 12 / 24 месяца**. Это не таймер аварийного PIN и не продление срока хранения файлов. Для production отдельно согласовать признаки активности, trusted server time, предупреждения и возможность предотвратить ошибочную очистку, связь с оплатой, backup и жизненным циклом аккаунта. Без подтверждённого алгоритма не выполнять необратимый scheduler.

## 6. Реализация

Два интерфейсных PIN проверяются строго отдельными верификаторами, без plaintext; security decisions серверные/доверенные, re-lock без зависимости от точности background JS. Развести `local_lock`, `local_wipe`, `server_revoke`, `cloud_delete`, `backup_preserve` по состояниям, обеспечивая offline safety и повтор после сбоев. Проверять multi-device, PIN rotation, server ACK lost, storage eviction, offline and interrupted wipe. Это **цель**, не изменяет production-код и не подтверждает security acceptance.
