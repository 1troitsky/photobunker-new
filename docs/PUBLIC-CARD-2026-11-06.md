Обычная кнопка Public card теперь открывает browser sheet внутри текущего Vue runtime с той же сессией и фото; основной маршрут и экран сохраняются. Переиспользован AppSheet, добавлены slide/reduced-motion, close/Escape/swipe, закрытие при смене аккаунта/блокировке. Lazy-load failure показывает сообщение/Retry. Внешний браузер запускается только отдельной кнопкой; для него готовится защищённая гостевая ссылка через существующий share pipeline, а не приватный cold-start route. Ссылка готовится, пока приложение активно; после подготовки нужно нажать готовую ссылку в той же панели, чтобы открыть браузер. Это web sheet PWA, не нативный Safari controller. Прежний внешний сценарий описан ниже как история отклонённой реализации.

[Фактический экран](evidence/public-card-sheet-20261106/public-card-sheet-390.png), [наблюдения](evidence/public-card-sheet-20261106/observations.json): открытие настоящей кнопкой меню Browser на synthetic fixture показывает фото, не вызывает window.open, сохраняет route/DOM/runtime; close/Escape/swipe возвращают тот же Browser. При ошибке подготовки внешней ссылки отображается сообщение, панель остаётся открытой; пустое окно браузера не открывается. Белый экран/перезапуск на устройстве владельца и успешный production publish для внешнего браузера — `NOT RUN`. Кнопки Public card в viewer и Browser открывают отдельное окно с `noopener,noreferrer`. Приватный предпросмотр `/photo-cards/:id` сохраняет identity/PIN/crypto guards, показывает явную пометку предпросмотра, без dock и возврата в галерею. Публичный доступ выдаётся только явным созданием защищённой ссылки `/c/:id#secret`; fragment удаляется перед запросами. Созданную ссылку можно открыть отдельно; гостю доступны только разрешённые поля и image/download scopes. Копирование/скачивание/Share находятся в header. Изображение сохраняет пропорции и естественную высоту, документ прокручивается.

В параметрах фото (`Edit → Данные фото`) и задания (`Правила`) есть enabled, автор/команда, дата съёмки, дата изменения, GPS, описание, tags, metadata. По TS enabled/GPS/описание включены, остальные выключены. Настройки задания копируются в metadata при capture, а не читаются из текущего задания при просмотре. Для non-E2EE пути сервер берёт сохранённую capture revision; схемы БД не менялись. Поля фото сохраняются через существующий metadata update, а новые ссылки получают свежую фильтрованную projection. Уже выданные immutable ссылки сохраняют прежний набор полей до отзыва/expiry; это явно написано в форме.

Фото для ссылки — существующая committed flattened version.
