# Public card — 2026-11-06

Предыдущая задача была неполной: агент самостоятельно оставил Public card на следующий этап. Новый кандидат `public-card-20261106-1`, активный runtime `compat/assignment-release/`.

Кнопки Public card в viewer и Browser открывают отдельное окно с `noopener,noreferrer`. Приватный предпросмотр `/photo-cards/:id` сохраняет identity/PIN/crypto guards, показывает явную пометку предпросмотра, без dock и возврата в галерею. Публичный доступ выдаётся только явным созданием защищённой ссылки `/c/:id#secret`; fragment удаляется перед запросами. Созданную ссылку можно открыть отдельно; гостю доступны только разрешённые поля и image/download scopes. Копирование/скачивание/Share находятся в header. Изображение сохраняет пропорции и естественную высоту, документ прокручивается.

В параметрах фото (`Edit → Данные фото`) и задания (`Правила`) есть enabled, автор/команда, дата съёмки, дата изменения, GPS, описание, tags, metadata. По TS enabled/GPS/описание включены, остальные выключены. Настройки задания копируются в metadata при capture, а не читаются из текущего задания при просмотре. Для non-E2EE пути сервер берёт сохранённую capture revision; схемы БД не менялись. Поля фото сохраняются через существующий metadata update, а новые ссылки получают свежую фильтрованную projection. Уже выданные immutable ссылки сохраняют прежний набор полей до отзыва/expiry; это явно написано в форме.

Фото для ссылки — существующая committed flattened version. Если правок ещё не было, явное Publish создаёт очищенную производную версию через существующий encrypted version pipeline; нужен edit/read/shareExternal grant. Незавершённая/конфликтующая новая версия запрещает автоматический fallback к старой или оригиналу. Передача raw original требует прежнего отдельного выбора и подтверждения. TTL не расширяется, ACL/crypto algorithms, recipient-read gates и emergency gate не изменены.
